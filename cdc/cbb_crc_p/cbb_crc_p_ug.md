## 1. 功能及应用场景

### 1.1 核心功能

CBB_CRC_P（Universal Parallel Combinational CRC Generator/Checker）是一款**通用并行组合逻辑 CRC 多项式生成器/校验器**。模块为纯组合逻辑电路，可在单周期内对最多 **2560 位**数据完成 CRC 计算。

### 1.2 主要特性

- 支持任意 CRC 多项式，位宽范围 2~64 位
- 支持 1~2560 位数据输入
- CRC 寄存器初始值可配置（全 0 或全 1）
- 生成 CRC 结果支持多种取反模式
- 支持 4 种比特/字节排序模式，适配不同协议
- 纯组合逻辑，单周期完成计算
- 同一模块实例可同时输出 CRC 生成值和校验结果

### 1.3 适用场景

| 应用场景 | 说明 |
|----------|------|
| 通信协议 CRC 校验 | 适用于 CRC-32、CCITT-CRC16、CRC-8 等标准协议 |
| 数据完整性保护 | 存储器/总线数据传输的 CRC 校验码生成与验证 |
| 数据帧校验 | 以太网、HDLC、USB 等协议的数据帧 FCS 字段处理 |
| 流式数据处理 | 作为流水线中的数据校验环节，单周期完成 CRC 计算 |

### 2.1 CRC 配置模式 — DS.CRC_P.FUNC.001

支持 8 种 CRC 配置模式（`CRC_CFG` = 0~7），控制 CRC 虚拟寄存器的初始值和生成 CRC 的比特取反方式：

| CRC_CFG | 寄存器初始值 | 生成 CRC 处理 | 典型应用 |
|---------|--------|--------------|----------|
| 0 | 全 0 | 不取反 | 特殊定制 |
| 1 | 全 1 | 不取反 | 特殊定制 |
| 2 | 全 0 | 偶数位取反 | ATM HEC |
| 3 | 全 1 | 偶数位取反 | 特殊定制 |
| 4 | 全 0 | 奇数位取反 | 特殊定制 |
| 5 | 全 1 | 奇数位取反 | 特殊定制 |
| 6 | 全 0 | 全取反 | 特殊定制 |
| 7 | 全 1 | 全取反 | CRC-32/CRC-16（最常用） |

### 2.2 位序/字节序配置 — DS.CRC_P.FUNC.002

支持 4 种比特和字节排序模式（`BIT_ORDER` = 0~3），适配不同协议的位序要求：

| BIT_ORDER | CRC 计算位序 | 字节序 | 适用条件 |
|-----------|-------------|--------|----------|
| 0 | MSB first | MSB first | 任意位宽 |
| 1 | LSB first | LSB first | 任意位宽 |
| 2 | MSB first | LSB first | DATA_WIDTH 和 POLY_SIZE 均为 8 的倍数 |
| 3 | LSB first | MSB first | DATA_WIDTH 和 POLY_SIZE 均为 8 的倍数 |

### 2.3 CRC 生成 — DS.CRC_P.FUNC.003

模块根据输入数据 `data_in`、多项式配置和位序配置，通过组合逻辑矩阵计算生成 CRC 校验码，由 `crc_out` 输出。

### 2.4 CRC 校验 — DS.CRC_P.FUNC.004

校验机制采用**双支路独立计算 + 内部中间余数比较**架构，不直接比较外部可见的 `crc_out` / `crc_in`。

**data 支路（正向运算）**：`data_in` 经过位序重排后，以初始寄存器值（由 `CRC_CFG` 决定的全 0 或全 1）为起点，经并行 CRC 正向组合逻辑矩阵运算，得到**内部原始中间余数 A**（未做输出取反处理）。例如：A = 0x7D14。

**crc_in 支路（反向补偿运算）**：接收端收到的 `crc_in` 是对方发送端发出的已翻转 CRC 码（即发送端的 `crc_out`）。硬件对 `crc_in` 依次执行：位序重排 → 抵消 `CRC_CFG` 输出翻转（取反 / 局部异或补偿）→ 反向多项式矩阵运算，最终**还原出未翻转中间余数 B**。正确数据下：B = 0x7D14 = A。

**判定逻辑**：硬件直接比较 A 与 B——`A XOR B == 全 0` → `crc_ok = 1`（数据无错）；任意 bit 不等 → `crc_ok = 0`（传输出错）。先抵消协议里的输出翻转和位序颠倒、还原到运算中途未修饰的中间余数再比较，是校验正确性的前提。

> **已知限制（重要）**：`crc_ok` 双支路比对仅在 `BIT_ORDER = 0` 下自洽。`BIT_ORDER` 为 1/2/3 时，`crc_in` 支路重排后的域与 A 支路不一致，无错链路也可能误报 `crc_ok = 0`。`crc_out` 生成路径不受此限制。需要使用片上校验/回环比对时，请将 `BIT_ORDER` 配置为 0，并在协议侧自行完成位序适配。

### 2.5 参数化多项式位宽 — DS.CRC_P.CFG.001

CRC 多项式位宽（`POLY_SIZE`）支持 2~64 位可配置，覆盖从 CRC-5 到 CRC-64 的所有标准多项式。

### 2.6 参数化数据位宽 — DS.CRC_P.CFG.002

输入数据位宽（`DATA_WIDTH`）支持 1~2560 位可配置，用户可根据数据通路宽度灵活设置。

### 2.7 多项式系数参数化 — DS.CRC_P.CFG.003

多项式系数通过 4 个 16 位参数（`POLY_COEF0`~`POLY_COEF3`）分段配置，支持任意 2~64 位多项式。`POLY_COEF0` 必须为奇数（常数项 x^0 系数为 1）。x^poly_size 项由 `POLY_SIZE` 隐含，无需显式指定。

### 2.8 纯组合逻辑设计 — DS.CRC_P.PERF.001

模块为纯组合逻辑电路，无时钟/复位信号，单周期完成 CRC 计算。关键路径延迟随 DATA_WIDTH 和 POLY_SIZE 增大而增加，用户需评估时序收敛。

## 3. 方案分析

### 3.1 原理分析

#### 3.1.1 CRC 计算基本原理

CRC（Cyclic Redundancy Check）基于多项式除法的模 2 运算（GF(2) 域）。对于给定的生成多项式 G(x)（poly_size 次），发送端将 k 位原始数据 D(x) 左移 poly_size 位后除以 G(x)，取余数 R(x) 作为 CRC 校验码附加到数据后发送。接收端将收到的完整数据帧（D(x) || R(x)）除以 G(x)，若余数为 0 则传输无误。

#### 3.1.2 并行组合逻辑计算原理

传统串行 CRC 计算使用 LFSR（线性反馈移位寄存器），每周期处理 1 位，需要 data_width 个周期。**并行 CRC** 利用组合逻辑矩阵，在单周期内一次性完成 data_width 位的 CRC 计算。

核心原理：将 LFSR 的递推关系展开为矩阵形式。对于 poly_size 位的 CRC 寄存器状态向量 S[n]：

```
S[n+1] = F × S[n] + G × d[n]
```

其中 F 为 poly_size × poly_size 的状态转移矩阵（由多项式决定），G 为 poly_size × 1 的输入矩阵。将上述递推展开 data_width 次后：

```
S[data_width] = F^data_width × S[0] + [F^(data_width-1)×G, ..., G] × [d[0], ..., d[data_width-1]]^T
```

整个表达式化简为组合逻辑：**CRC_OUT = H × CRC_INIT + M × DATA_IN**，其中 H 和 M 为多项式参数决定的组合逻辑矩阵。

#### 3.1.3 位序处理原理

位序处理影响数据比特和 CRC 比特的计算顺序：

- **MSB first**：数据最高位（data_in[DATA_WIDTH-1]）作为多项式除法的首位
- **LSB first**：数据最低位（data_in[0]）作为多项式除法的首位
- **字节序**：在 8 位对齐模式下，每个字节内部的比特序由位序决定，字节间的排列顺序由字节序决定

### 3.2 设计方案

#### 3.2.1 整体架构

```
                    ┌──────────────────────────────────────────────────────────┐
                    │                      CBB_CRC_P                            │
                    │                                                           │
  data_in ───────► [Bit Reorder] ──► [CRC Forward Matrix] ──► [Bit Inversion] ─► crc_out
                    │    │                │                                       │
                    │    │                │  内部原始中间余数 A                     │
                    │    │                │       │                               │
                    │    │                │       v                               │
                    │    │                │   [A XOR B] ─────────────────────────► crc_ok
                    │    │                │       ^                               │
                    │    │                │       │                               │
                    │    │                │  内部原始中间余数 B                     │
                    │    │                │       │                               │
  crc_in ────────► [Bit Reorder] ──► [Inversion Cancel] ──► [CRC Reverse Matrix] │
                    │                                                           │
                    └──────────────────────────────────────────────────────────┘
```

**逻辑链总览**：

| 步骤 | 发送端（生成） | 接收端（校验） |
|------|---------------|---------------|
| ① 输入 | `data_in` | `data_in` + `crc_in`（= 对方 `crc_out`） |
| ② 位序 | Bit Reorder | Bit Reorder（data 和 crc_in 各自重排） |
| ③ 矩阵 | 正向 CRC 矩阵 → 中间余数 A | 反向 CRC 矩阵 → 中间余数 B（需先抵消输出翻转） |
| ④ 输出翻转 | 按 `CRC_CFG` 翻转 A → `crc_out` | — |
| ⑤ 校验 | — | A XOR B → `crc_ok` |

> **关键点**：校验不拿外部可见的 `crc_out` 和 `crc_in` 直接对比（它们在协议翻转下永远不相等），而是先将两者各自还原到**运算中途未修饰的内部中间余数**，再比较 A 与 B。

#### 3.2.2 位序重排模块（Bit Reorder）

根据 `BIT_ORDER` 配置，对输入数据 `data_in` 和输入 CRC 值 `crc_in` 进行比特重排：

- BIT_ORDER = 0：不重排（MSB first, MSB first 字节序）
- BIT_ORDER = 1：完全反转（LSB first, LSB first 字节序）
- BIT_ORDER = 2：字节内不反转、字节间反转（仅 8 位对齐时可用）
- BIT_ORDER = 3：字节内反转、字节间不反转（仅 8 位对齐时可用）

#### 3.2.3 Data 支路：正向 CRC 计算矩阵（CRC Forward Matrix）

`data_in` 经过位序重排后，以 `CRC_CFG` 决定的初始寄存器值（偶数 = 全 0，奇数 = 全 1）为起点，送入**正向 CRC 组合逻辑矩阵**进行并行多项式除法，计算得到**内部原始中间余数 A**（未经输出翻转修饰）。

正向矩阵由 `POLY_SIZE`、`DATA_WIDTH`、多项式系数（`POLY_COEF0`~`POLY_COEF3`）以及位序配置共同决定。

中间余数 A 分两路输出：
- 一路送入比特取反模块，按 `CRC_CFG` 翻转后作为 `crc_out` 输出（生成路径）
- 一路送入 A XOR B 比较器（校验路径）

#### 3.2.4 crc_in 支路：反向补偿运算（CRC Reverse Matrix）

接收端收到的 `crc_in` 是发送端发出的已翻转 `crc_out`。要还原出未翻转中间余数 B，需依次执行三步反向补偿：

1. **位序重排**：按 `BIT_ORDER` 对 `crc_in` 进行与 data 支路一致的比特/字节重排
2. **抵消输出翻转**（Inversion Cancel）：根据 `CRC_CFG`，对重排后的 `crc_in` 执行与输出翻转相反的补偿操作，恢复为翻转前的形式
   - `CRC_CFG` = 0/1（不取反）：无需抵消
   - `CRC_CFG` = 2/3（偶数位取反）：对偶数位再次取反（异或补偿）
   - `CRC_CFG` = 4/5（奇数位取反）：对奇数位再次取反（异或补偿）
   - `CRC_CFG` = 6/7（全取反）：全部再次取反
3. **反向多项式矩阵运算**：将抵消翻转后的值送入**反向 CRC 组合逻辑矩阵**，通过逆矩阵运算还原出发送端那份未翻转的中间余数 B

在数据无错条件下，还原出的 B 应与 data 支路正向算出的 A 相等（如均等于 0x7D14）。

#### 3.2.5 比特取反与取反抵消（Bit Inversion & Inversion Cancel）

**输出翻转（生成路径）**：根据 `CRC_CFG` 配置，对正向矩阵算出的中间余数 A 进行取反处理，生成最终 `crc_out`：

| CRC_CFG | 输出翻转方式 |
|---------|-------------|
| 0/1 | 不取反 |
| 2/3 | 偶数位取反（bits 0, 2, 4, ...） |
| 4/5 | 奇数位取反（bits 1, 3, 5, ...） |
| 6/7 | 全取反 |

**取反抵消（校验路径）**：crc_in 支路在送入反向矩阵前，必须先执行与输出翻转相反的补偿操作，恢复翻转前形式：

| CRC_CFG | 翻转抵消方式 |
|---------|-------------|
| 0/1 | 无需抵消 |
| 2/3 | 偶数位再次取反（异或 0xAAAA...掩码） |
| 4/5 | 奇数位再次取反（异或 0x5555...掩码） |
| 6/7 | 全取反 |

#### 3.2.6 校验结果判定（A XOR B）

硬件直接比较 data 支路算出的**中间余数 A** 与 crc_in 支路还原出的**中间余数 B**：

```
crc_ok = (A XOR B == 全 0) ? 1'b1 : 1'b0
```

- `A XOR B == 全 0`（即 A 与 B 每一位均相等）→ `crc_ok = 1`，数据无错
- `A XOR B != 全 0`（任意 bit 不等）→ `crc_ok = 0`，传输出错

**一句话理清逻辑链**：
1. **发送**：数据 → 正向矩阵算出中间余数 A → 按 `CRC_CFG` 翻转 A → `crc_out`（发出去）
2. **接收**：收到 `crc_out` 作为 `crc_in` → 位序重排 → 抵消翻转 → 反向矩阵还原出 B
3. **判定**：比较内部原始中间余数 A 与 B 是否相等 → `crc_ok`

> **⚠️ 关键认知**：不拿外部可见的 `crc_out` / `crc_in` 直接对比——必须**先抵消协议里的输出翻转和位序颠倒**，还原到运算中途未修饰的中间余数再比较。如果直接拿 `crc_in` 和 `crc_out` 对比，两者在翻转差异下永远无法相等，校验直接失效。

#### 3.2.7 使用模式

| 使用场景 | crc_in | crc_out | crc_ok |
|----------|--------|---------|--------|
| 仅 CRC 生成 | 接全 0 | 连接使用 | 悬空 |

## 6. 时序图

### 6.1 CRC 生成时序

```
  data_in   -----<  D0  >-----<  D1  >-----<  D2  >-----
                      |              |              |
                      v              v              v
  crc_out   -----< CRC0 >-----< CRC1 >-----< CRC2 >-----
```

- 输入 `data_in` 变化后，经过组合逻辑延迟 Tpd，`crc_out` 输出对应的 CRC 结果
- 本模块为纯组合逻辑，无时钟节拍，延迟由综合后的关键路径决定

### 6.2 CRC 校验时序

```
  data_in   -----< D0+CRC >-----< D1+CRC >-----< D2+CRC >-----
  crc_in    -----<  CRC0  >-----<  CRC1  >-----<  CRC2  >-----
                      |              |              |
                      v              v              v
  crc_ok    -----< 1'b1/0 >-----< 1'b1/0 >-----< 1'b1/0 >-----
```

- `data_in` 和 `crc_in` 同时有效时，经过组合逻辑延迟 Tpd，`crc_ok` 输出校验结果
- `crc_ok = 1` 表示 CRC 校验通过，`crc_ok = 0` 表示校验失败

### 6.3 时序约束建议

由于模块为纯组合逻辑，使用时需要根据系统时钟频率评估组合逻辑延迟：

- 输入信号应在时钟周期开始后尽早稳定
- 输出信号应在时钟沿前满足 setup 时间要求
- 关键路径延迟随 DATA_WIDTH 和 POLY_SIZE 增大而增加

### 7.4 时序说明

- 模块为纯组合逻辑，所有输入到输出的路径均为组合路径
- 非寄存器输出：所有输出（crc_out、crc_ok）均为组合逻辑输出，无内部寄存器
- 关键路径级数随 DATA_WIDTH 和 POLY_SIZE 增大：8bit→8级，16bit→13级，32bit→14级
- 三配置在 0.7ns 时钟周期下均无时序违例（Slack > 0）
- 最大可工作频率（组合延迟倒数）：配置A ~7.9GHz，配置B ~4.0GHz，配置C ~2.9GHz（理论值，实际需考虑 setup/hold margin 和外部的 input/output delay）
- 外部系统需根据综合后的时序报告评估可承受的组合逻辑延迟
