## 1. 功能及应用场景

CBB_ARB_DP 是一款参数化的同步动态优先级仲裁器（Dynamic Priority Arbiter），支持最多 32 个客户端并发请求仲裁。每个客户端可通过独立的优先级输入端口 `prior` 实时配置仲裁优先级，优先级数值可在运行时动态改变。当多个客户端被配置为相同优先级时，组件自动回退到基于客户端索引的静态优先级仲裁策略。

**核心功能：**

| 功能 | 说明 |
|------|------|
| 动态优先级仲裁 | 每个客户端独立配置 `ceil(log₂n)` 位优先级，数值越小优先级越高 |
| 静态优先级回退 | 多客户端同优先级时，按 `req[0]`（最高）→ `req[n-1]`（最低）固定顺序仲裁 |
| Park 功能 | 无有效请求时，授权挂起在 `PARK_INDEX` 指定客户端，节省下一拍仲裁周期 |
| Lock 功能 | 已授权客户端可通过 `lock` 锁定仲裁器，独占资源 |
| Mask 功能 | 通过 `mask` 独立屏蔽任意客户端请求 |
| 输出模式可配置 | 支持寄存器输出（一拍延迟）与组合逻辑输出两种模式 |

**典型应用场景：**

- 多主机共享总线仲裁（AXI/AHB 总线矩阵）
- 多通道 DMA 请求调度
- 多端口存储控制器请求仲裁
- 网络包调度与 QoS 管理
- 中断控制器优先级调度

| DS.ARB_DP.FUNC.002 | 静态优先级回退 | FUNC | 多客户端同优先级时按索引固定顺序裁决，所有优先级相同时退化为纯静态优先级仲裁器 |
| DS.ARB_DP.FUNC.003 | Park 功能 | FUNC | 无有效请求时授权挂起在 `PARK_INDEX` 指定客户端，可通过 `PARK_MODE` 启用/禁用 |

| DS.ARB_DP.FUNC.005 | Mask 功能 | FUNC | 可独立屏蔽任意客户端请求，非锁定状态下被屏蔽客户端不参与仲裁 |
| DS.ARB_DP.FUNC.006 | 优先级顺序 | FUNC | 仲裁决策优先级由高到低依次为：Lock → Mask → 正常仲裁 → Park |

| DS.ARB_DP.CFG.002 | 客户端数量可配置 | CFG | `NUM_MASTERS` 参数支持 2 ~ 32 范围配置 |
| DS.ARB_DP.INTF.001 | 状态标志输出 | INTF | 提供 `granted`、`locked`、`parked` 三个状态标志信号 |

### 2.1 动态优先级仲裁 — DS.ARB_DP.FUNC.001

每个客户端通过 `prior` 端口独立配置优先级，位宽 `BW = ceil(log₂(NUM_MASTERS))`。数值越小优先级越高（0 为最高优先级）。`prior` 向量按客户端索引从低到高拼接：`prior[BW-1:0]` 对应 client[0]，`prior[2*BW-1:BW]` 对应 client[1]，以此类推。

当 `NUM_MASTERS` 不是 2 的幂次时，每个优先级字段的合法值范围为 `0 ~ NUM_MASTERS-1`。`NUM_MASTERS ~ 2^BW-1` 之间的值为非法值，使用将导致仲裁结果错误。

### 2.2 静态优先级回退 — DS.ARB_DP.FUNC.002

当多个客户端具有相同的 `prior` 值时，仲裁器按客户端索引固定顺序裁决：`req[0]` 优先级最高，`req[NUM_MASTERS-1]` 优先级最低。当所有 `prior` 值相同时，组件退化为纯静态优先级仲裁器。

### 2.3 Park 功能 — DS.ARB_DP.FUNC.003

通过 `PARK_MODE` 参数启用（1：启用，0：禁用）。启用后，当输入端无任何有效请求时，仲裁器将 `gnt` 指向 `PARK_INDEX` 指定的客户端，同时 `parked` 置 1。
禁用 Park 后，无请求时所有 `gnt` 输出为 0，`parked` 信号不存在。

### 2.4 Lock 功能 — DS.ARB_DP.FUNC.004

已获授权的客户端可通过 `lock[gnt_idx] = 1` 锁定仲裁器。锁定期间当前授权客户端独占资源，其他所有客户端请求被屏蔽。`lock` 撤消后恢复正常仲裁。

Lock 与 Mask 交互规则：锁定状态下对任何客户端（含当前锁定客户端）的 `mask` 操作均不影响当前授权，锁定解除后 `mask` 才生效。

### 2.5 Mask 功能 — DS.ARB_DP.FUNC.005

通过 `mask` 向量可独立屏蔽任意客户端。`mask[i] = 1` 时 client[i] 的请求不参与仲裁。非锁定状态下，当前获授权客户端被 mask 后，下一拍立即撤销授权并重新仲裁。

### 2.6 优先级顺序 — DS.ARB_DP.FUNC.006

仲裁决策按以下优先级由高到低执行：

| 优先级 | 机制 | 说明 |
|--------|------|------|
| 1（最高） | Lock | 若当前授权客户端 `lock=1`，锁定授权不变，屏蔽其他所有请求 |
| 2 | Mask | 非锁定状态下，`mask=1` 的客户端请求被过滤，不参与仲裁 |
| 3 | 正常仲裁 | 在剩余有效请求中按动态优先级 + 静态回退规则选出获胜客户端 |
| 4（最低） | Park | 若无任何有效请求且 `PARK_MODE=1`，授权挂起到 `PARK_INDEX` |

### 2.7 输出模式可配置 — DS.ARB_DP.CFG.001

通过 `OUTPUT_MODE` 参数配置输出模式：
- `OUTPUT_MODE = 1`（寄存器输出）：`gnt` 及状态信号在 `clk` 上升沿更新，相对输入延迟一拍，输出时序干净
- `OUTPUT_MODE = 0`（组合逻辑输出）：`gnt` 及状态信号为组合逻辑输出，随输入实时变化，减少一拍延迟

### 2.8 客户端数量可配置 — DS.ARB_DP.CFG.002

`NUM_MASTERS` 参数支持 2 ~ 32 范围配置，适配不同规模的仲裁场景。

### 2.9 状态标志输出 — DS.ARB_DP.INTF.001

| 状态标志 | 功能 |
|----------|------|
| `granted` | 授权有效标志，表示当前存在有效的资源授权（至少有一个有效请求且已发出授权） |
| `locked` | 锁定状态标志，表示仲裁器正被某客户端锁定 |
| `parked` | Park 状态标志（仅 `PARK_MODE=1` 时存在），表示当前无有效请求、授权处于挂起状态 |

## 3. 方案分析

### 3.1 核心原理

动态优先级仲裁的本质是在每拍从 n 个请求源中选出"优先级最高"的一个。优先级由两部分信息唯一确定：

1. **动态优先级值 `prior`**：由外部实时配置，数值越小优先级越高
2. **静态索引序号**：作为同优先级时的 tie-breaker，索引越小优先级越高

因此，仲裁的比较键可定义为元组 `(prior_val, index)`，按字典序升序排列，取最小者即为获胜客户端。

### 3.2 仲裁决策流程

```
Step 1: 请求过滤
        —— 排除 mask=1 的客户端（锁定状态下 mask 不影响当前授权）
        —— 排除 req=0 的客户端

Step 2: 锁定判断
        —— 若当前授权客户端 lock=1，保持当前授权不变，跳过后续步骤

Step 3: 优先级比较
        —— 在有效请求中选 prior 值最小的客户端

Step 4: 静态回退
        —— 若多个客户端 prior 值相同，选择索引最小者

Step 5: Park 判断
        —— 若无有效请求且 PARK_MODE=1，gnt 指向 PARK_INDEX
        —— 若无有效请求且 PARK_MODE=0，所有 gnt 输出为 0

Step 6: 授权输出
        —— 对应 gnt 位置 1（one-hot），更新状态标志
```

### 3.3 硬件架构设计

#### 3.3.1 Request Filter & Mask（请求过滤与屏蔽）

将 `req` 与 `~mask` 按位与，得到有效请求向量 `valid_req`。被屏蔽客户端的请求不参与后续优先级比较。

```verilog
assign valid_req = req & ~mask;
```

**特殊情况**：锁定状态下 mask 不影响当前授权。实现时通过 MUX 在锁定状态下将当前授权客户端的 mask 视为 0。

#### 3.3.2 Priority Comparator（优先级比较）

采用**顺序线性遍历最小值择优算法**，从 client[0] 到 client[NUM_MASTERS-1] 单轮遍历所有有效请求，实时维护当前最优候选者，遍历结束时即得全局最优。

算法流程：
1. 初始化：最优优先级 `best_prior = {BW{1'b1}}`（最大值），最优索引 `best_idx = 0`
2. 从 `i = 0` 到 `NUM_MASTERS-1` 顺序遍历：
   - 若 `valid_req[i] == 1'b0`：跳过
   - 若 `prior[i] < best_prior`：更新 `best_prior = prior[i]`，`best_idx = i`
   - 若 `prior[i] == best_prior`：不更新（保留索引较小者，实现静态回退）
3. 遍历结束，`best_idx` 即为获胜客户端

算法特性：单轮遍历即得全局最优，天然支持静态回退（先到先得），关键路径为 `NUM_MASTERS` 级比较器级联。

#### 3.3.3 Lock Control（锁定控制）

维护一个锁定状态寄存器，记录当前锁定的客户端索引。当 `lock[current_gnt_idx] == 1'b1` 时进入锁定状态：

- 绕过优先级比较结果，强制保持当前授权
- `locked` 输出置 1
- 其他客户端的请求被忽略

锁定的**进入条件**：当前授权有效 且 对应 `lock` 为 1
锁定的**退出条件**：对应 `lock` 变为 0

#### 3.3.4 Park Logic（挂起逻辑）

当 `valid_req == {NUM_MASTERS{1'b0}}`（无有效请求）且 `PARK_MODE == 1` 时：
- `gnt` 输出 `PARK_INDEX` 对应的 one-hot 编码
- `parked` 置 1
- `granted` 置 0（无实际授权）

当 `PARK_MODE == 0` 时，`parked` 恒为 0，无请求时 `gnt` 全为 0。

#### 3.3.5 Output Register（输出寄存器）

根据 `OUTPUT_MODE` 参数控制输出路径：
- `OUTPUT_MODE = 1`：在输出端插入一级寄存器，`gnt`、`granted`、`locked`、`parked` 均为寄存器输出
- `OUTPUT_MODE = 0`：输出直接由组合逻辑驱动

### 3.4 仲裁示例

**场景**：NUM_MASTERS = 4，PARK_MODE = 1，PARK_INDEX = 0

| 时刻 | req | prior | mask | lock | 仲裁结果 | 说明 |
|------|-----|-------|------|------|----------|------|
| T0 | 4'b0000 | — | 4'b0000 | 4'b0000 | gnt=0001, parked=1 | 无请求，park 到 client[0] |
| T1 | 4'b1010 | {2'd1,2'd0,2'd1,2'd0} | 4'b0000 | 4'b0000 | gnt=0100, granted=1 | client[1]和client[3]同优先级(0)，但 client[1]索引更小 |
| T2 | 4'b1010 | {2'd1,2'd0,2'd1,2'd0} | 4'b0100 | 4'b0000 | gnt=1000, granted=1 | client[1]被 mask，client[3]获胜 |
| T3 | 4'b1111 | {2'd2,2'd1,2'd1,2'd3} | 4'b0000 | 4'b0100 | gnt=0100, locked=1 | client[1]优先级最高，且 lock 生效 |

## 4. 配置参数

| 参数 | 配置范围 | 默认值 | 描述 |
|------|----------|--------|------|
| `NUM_MASTERS` | 2 ~ 32 | 4 | 仲裁器客户端数量，决定 `req`/`gnt`/`lock`/`mask` 位宽 |
| `BW` | — | `ceil(log₂(NUM_MASTERS))` | 单个客户端优先级字段位宽，由 `NUM_MASTERS` 自动计算，`prior` 总位宽为 `NUM_MASTERS × BW` |
| `PARK_MODE` | 0 或 1 | 1 | Park 功能使能：1 = 启用 Park 逻辑（`parked` 有效）；0 = 禁用 Park 逻辑 |
| `PARK_INDEX` | 0 ~ NUM_MASTERS-1 | 0 | Park 目标客户端索引，当无有效请求时 `gnt` 默认指向该客户端 |
| `OUTPUT_MODE` | 0 或 1 | 1 | 输出模式：1 = 寄存器输出（含输出寄存器级，一拍延迟）；0 = 组合逻辑输出（无输出寄存器） |

## 5. 接口

| 信号名 | 位宽 | I/O | 时钟域 | 描述 |
|--------|------|-----|--------|------|
| `clk` | 1 | I | clk | 全局时钟输入 |
| `rst_n` | 1 | I | - | 异步复位（低有效），复位所有内部寄存器 |
| `req` | NUM_MASTERS | I | clk | 请求向量，每位对应一个客户端请求，需与 `clk` 同步 |
| `prior` | NUM_MASTERS × BW | I | clk | 动态优先级配置向量，由 NUM_MASTERS 个 BW 位宽的优先级字段拼接。`prior[(i+1)*BW-1 : i*BW]` 对应 client[i] 的优先级值，数值越小优先级越高。其中 `BW = ceil(log₂(NUM_MASTERS))` |
| `lock` | NUM_MASTERS | I | clk | 锁定请求向量，`lock[i] = 1` 锁定当前授权给 client[i]，锁定期间独占仲裁资源。不使用时接 `{NUM_MASTERS{1'b0}}`（全 0） |
| `mask` | NUM_MASTERS | I | clk | 屏蔽控制向量，`mask[i] = 1` 屏蔽 client[i] 请求，被屏蔽客户端不参与仲裁。不使用时接 `{NUM_MASTERS{1'b0}}`（全 0） |
| `gnt` | NUM_MASTERS | O | clk | 授权输出向量（one-hot 编码），对应位为 1 表示该客户端获得授权。 |
| `parked` | 1 | O | clk | Park 状态标志（高有效），`PARK_MODE=1` 时存在。表示当前无有效请求，授权默认指向 `PARK_INDEX`。 |
| `granted` | 1 | O | clk | 授权有效标志（高有效），表示当前存在有效的资源授权。 |
| `locked` | 1 | O | clk | 锁定状态标志（高有效），表示仲裁器正被某客户端锁定。 |

**注：** `OUTPUT_MODE=1`（寄存器输出）时，`gnt`、`parked`、`granted`、`locked` 均为寄存器输出，在时钟上升沿更新；`OUTPUT_MODE=0`（组合逻辑输出）时，上述信号均为组合逻辑输出，随输入实时变化。

### 7.4 时序说明

- **寄存器输出模式（OUTPUT_MODE=1）**：`gnt` 及状态信号从寄存器直接输出，输出路径延迟最小（CK→Q），实测 REGOUT slack ≥ 0.39ns，外部组合逻辑级数充裕。
- **关键路径分析**：关键路径为 **REGIN**（输入→首级寄存器），即 `req/prior/mask/lock → 遍历比较逻辑 → curr_gnt` 的组合路径。该路径逻辑级数随 NUM_MASTERS 线性增长：

| NUM_MASTERS | 时钟约束 | REGIN 逻辑级数 | 路径延迟 | Slack | 频率 |
|:---:|:---:|:---:|------|:---:|:---:|
| 4 (默认) | 0.7ns | 18 | 0.345ns | +0.085ns | 1.43 GHz |
| 8 | 0.7ns | 26 | 0.427ns | +0.295ns | 1.43 GHz |
| 32 | 1.2ns | — | — | +0.0001ns | 833 MHz |

- **频率选择建议**：N ≤ 8 可在 0.7ns（1.43GHz）下稳定通过；N = 32 需放宽至 1.2ns（833MHz）。
