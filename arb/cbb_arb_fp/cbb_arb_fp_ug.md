## 1. 功能及应用场景

### 1.1 核心功能

`CBB_ARB_FP` 是一款参数化同步仲裁器 IP，采用**固定静态优先级（Fixed Priority）**仲裁策略，支持 2~32 个客户端竞争共享资源。模块提供 Lock（锁定）、Park（停靠）、Mask（屏蔽）三种辅助控制机制，并支持输出寄存/组合输出两种模式，适配不同时序收敛需求。

### 1.2 适用场景

- **总线仲裁**：多主设备共享总线的优先级仲裁
- **DMA 控制器**：多个 DMA 通道访问共享存储的优先级调度
- **网络交换**：数据包调度与端口仲裁
- **控制逻辑**：有限状态机中的资源分配控制

## 2. 规格

### 2.1 静态优先级仲裁 — DS.CBB_ARB_FP.FUNC.001

采用固定静态优先级（Fixed Priority）方案，各客户端优先级由端口索引固定决定，优先级由高到低为：

```
req[0] > req[1] > req[2] > ... > req[NUM_MASTERS-1]
```

- `req[0]`：最高优先级
- `req[NUM_MASTERS-1]`：最低优先级
- 优先级不可动态调整，客户端需按优先级要求接入对应端口
- 同时有多个请求时，优先级最高的客户端获得授权
- 高优先级客户端持续请求会导致低优先级客户端饿死（starvation），系统设计时需评估

### 2.2 Lock 锁定机制 — DS.CBB_ARB_FP.FUNC.002

Lock 机制允许已获得授权的客户端独占共享资源，适用于 DMA 传输等需要连续占用资源的场景。

- **进入锁定**：客户端 i 获得授权后，置起 `lock[i] = 1`，仲裁器进入锁定状态
- **锁定行为**：锁定期间当前客户端持续占用资源，其他所有客户端的请求均被屏蔽，优先级仲裁暂停
- **退出锁定**：客户端释放 `lock[i] = 0` 后，下一时钟周期仲裁器退出锁定状态，重新进行正常优先级仲裁
- **状态指示**：锁定状态通过 `locked` 输出标志指示（高有效）
- **约束**：仅当前已获授权的客户端可锁定；未授权客户端置起 lock 无效

### 2.3 Park 停靠机制 — DS.CBB_ARB_FP.FUNC.003

Park 机制在无任何客户端发起请求时，将资源默认授予指定客户端，避免授权信号悬空，同时使停靠客户端可快速响应。

- **停靠条件**：`PARK_MODE = 1` 且所有 `req[i]` 均为 0
- **停靠目标**：资源授予 `PARK_INDEX` 参数指定的客户端，`gnt[PARK_INDEX] = 1`
- **停靠退出**：任意客户端发起请求后，下一周期退出停靠状态，进入正常优先级仲裁
- **停靠关闭**：`PARK_MODE = 0` 时停靠逻辑禁用，无请求时所有 `gnt[i]` 均为 0
- **状态指示**：停靠状态通过 `parked` 输出标志指示（高有效）

### 2.4 Mask 屏蔽机制 — DS.CBB_ARB_FP.FUNC.004

Mask 机制允许动态屏蔽指定客户端的请求，被屏蔽的客户端不参与仲裁，适用于需要临时禁用某客户端的场景。

- **屏蔽设置**：`mask[i] = 1` 屏蔽客户端 i，该客户端的 `req[i]` 不参与仲裁
- **屏蔽解除**：`mask[i] = 0` 解除屏蔽，客户端 i 恢复正常参与仲裁
- **非锁定状态下的屏蔽**：若被屏蔽的客户端 i 当前正持有授权，下一周期收回授权，对剩余未屏蔽请求重新仲裁
- **锁定状态下的屏蔽**：对当前已授权的锁定客户端设置 mask 无效，授权不收回；对其他客户端 mask 正常生效
- **全部屏蔽**：所有客户端均被屏蔽时，行为等同于无请求（进入 Park 或全部 gnt=0）

### 2.5 状态标志输出 — DS.CBB_ARB_FP.FUNC.005

模块提供三个状态标志输出，用于外部逻辑判断当前仲裁器工作状态。

- **`granted`**：高电平表示当前仲裁器已将资源授予某个正在有效请求的客户端（区别于停靠状态）
  - `granted = 1` 当且仅当存在有效请求且仲裁器已给出授权（非停靠、非全部屏蔽）
- **`parked`**：高电平表示仲裁器处于停靠状态
  - `parked = 1` 当且仅当 `PARK_MODE = 1` 且无有效请求
  - `PARK_MODE = 0` 时 `parked` 恒为 0
- **`locked`**：高电平表示仲裁器已被某客户端锁定
  - `locked = 1` 当且仅当某客户端已通过 lock 信号锁定资源

### 2.6 功能优先级顺序 — DS.CBB_ARB_FP.FUNC.006

仲裁器内部各机制的优先级从高到低为：

| 优先级 | 机制 | 说明 |
|--------|------|------|
| 1  | Lock | 锁定期间独占资源，无视其他所有条件 |
| 2 | Mask | 屏蔽指定客户端请求 |
| 3  | 静态优先级 | 在剩余有效请求中按固定优先级仲裁 |
| 4 | Park | 无请求时默认授予指定客户端 |

### 2.7 单周期仲裁延迟 — DS.CBB_ARB_FP.PERF.001

仲裁逻辑在单个时钟周期内完成请求采样到授权输出的完整路径。

- **OUTPUT_MODE = 1（寄存输出）**：从 `req`/`lock`/`mask` 输入经过 Input Stage → Arbitration Engine → Output Registers，一个时钟周期后 `gnt` 输出有效
- **OUTPUT_MODE = 0（组合输出）**：从 `req`/`lock`/`mask` 输入到 `gnt`、`parked`、`granted`、`locked` 输出均为纯组合逻辑路径，同周期内生效
- 时序收敛的关键路径为优先级编码器组合逻辑，延迟随 NUM_MASTERS 增大而增加

### 2.8 时钟与复位接口 — DS.CBB_ARB_FP.INTF.001

- **时钟 `clk`**：单时钟域设计，所有输入信号须与 `clk` 上升沿同步，所有寄存器由 `clk` 上升沿驱动
- **复位 `rst_n`**：异步复位（低电平有效），复位后所有寄存器清零（所有 `gnt`、状态标志均为 0）
- 复位释放需满足寄存器 recovery/removal 时序要求

### 2.9 请求/授权接口 — DS.CBB_ARB_FP.INTF.002

- **请求输入 `req[NUM_MASTERS-1:0]`**：每位对应一个客户端，`req[i] = 1` 表示客户端 i 请求资源
- **授权输出 `gnt[NUM_MASTERS-1:0]`**：独热码（one-hot），`gnt[i] = 1` 表示客户端 i 获得资源授权
  - 最多只有 1 位为 1（互斥授权）
  - OUTPUT_MODE=1 时寄存器输出，OUTPUT_MODE=0 时组合输出
- 所有请求信号须与 `clk` 同步，不支持异步请求

### 2.10 控制接口 — DS.CBB_ARB_FP.INTF.003

- **锁定控制 `lock[NUM_MASTERS-1:0]`**：每位对应一个客户端，`lock[i] = 1` 表示客户端 i 请求锁定资源（仅当前已授权客户端可生效）
- **屏蔽控制 `mask[NUM_MASTERS-1:0]`**：每位对应一个客户端，`mask[i] = 1` 表示屏蔽客户端 i
- 两个控制信号均为同步输入，与 `clk` 上升沿对齐

### 2.11 客户端数量配置 — DS.CBB_ARB_FP.CFG.001

- **参数 `NUM_MASTERS`**：仲裁器支持的客户端数量，取值范围 2 ~ 32，默认值 4
- NUM_MASTERS 决定了 `req`、`lock`、`mask`、`gnt` 的位宽
- NUM_MASTERS 越大，优先级编码器组合逻辑级数越大，时序收敛难度增加

### 2.12 停靠使能配置 — DS.CBB_ARB_FP.CFG.002

- **参数 `PARK_MODE`**：停靠功能使能开关，取值 0 或 1，默认值 1
- `PARK_MODE = 1`：启用停靠逻辑，无请求时资源默认授予 `PARK_INDEX` 指定客户端
- `PARK_MODE = 0`：禁用停靠逻辑，无请求时无客户端获得授权，`parked` 标志恒为 0

### 2.13 停靠索引配置 — DS.CBB_ARB_FP.CFG.003

- **参数 `PARK_INDEX`**：停靠目标客户端索引号，取值范围 0 ~ NUM_MASTERS-1，默认值 0
- 仅在 `PARK_MODE = 1` 时有效
- 该参数值必须小于 NUM_MASTERS，超出范围会导致功能错误

### 2.14 输出模式配置 — DS.CBB_ARB_FP.CFG.004

- **参数 `OUTPUT_MODE`**：输出模式选择，取值 0 或 1，默认值 1
- `OUTPUT_MODE = 1`：`gnt` 经一级寄存器输出（寄存输出模式），有利于时序收敛，适用于高频设计
- `OUTPUT_MODE = 0`：`gnt` 为组合逻辑直接输出（组合输出模式），零周期延迟，适用于低延迟设计
- `parked`、`granted`、`locked` 标志的输出模式与 `gnt` 一致，由 `OUTPUT_MODE` 统一控制

## 3. 方案分析

### 3.1 核心原理

固定优先级仲裁器的核心是**优先级编码器（Priority Encoder）**。对于 NUM_MASTERS 位请求向量 `req[NUM_MASTERS-1:0]`，仲裁器找到其中为 1 的位中索引最小（优先级最高）的那一位，输出对应的独热码授权。

布尔逻辑表达：对于第 i 位，其获得授权的条件为：

```
gnt[i] = req[i] AND (req[0] == 0) AND (req[1] == 0) AND ... AND (req[i-1] == 0)
       = req[i] AND (|req[i-1:0] == 0)
```

即：第 i 位有请求，且所有优先级高于它的位均无请求。

### 3.2 设计方案

#### 3.2.1 整体结构

模块内部划分为四级流水（output_mode = 1 时）：

```
                   rst_n
                     │
   req  ──┐         ▼
   mask ──┤  ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
   lock ──┤  │  Input       │────▶│  Arbitration │────▶│  Output      │────▶ gnt
          │  │  Stage       │     │  Engine      │     │  Registers   │
   clk  ──┤  └─────────────┘     └─────────────┘     └─────────────┘
                                                                            │
                                                                            ▼
                                                                      ┌─────────────┐
                                                                      │  Flag Logic  │
                                                                      └─────────────┘
                                                                       │      │      │
                                                                       ▼      ▼      ▼
                                                                     parked granted locked
```

- **Input Stage**：对输入信号进行 mask 处理、lock 状态维护
- **Arbitration Engine**：核心优先级仲裁逻辑
- **Output Registers**：输出寄存器（仅 output_mode = 1）
- **Flag Logic**：状态标志生成（parked / granted / locked）

当 `OUTPUT_MODE = 0` 时，去掉 Output Registers 级，gnt 直接由 Arbitration Engine 组合输出。

#### 3.2.2 仲裁引擎设计

**Step 1 — Mask 处理**：将原始请求与 mask 信号按位与，得到有效请求向量：

```
eff_req[i] = req[i] AND (mask[i] == 0)
```

**Step 2 — Lock 判断**：若当前处于锁定状态且 lock 仍有效，保持当前授权不变；否则进入正常仲裁。

**Step 3 — Park 判断**：若无有效请求且 PARK_MODE 使能，授权给 PARK_INDEX。

**Step 4 — 优先级仲裁**：对有效请求向量执行优先编码，得到最高优先级请求位。

#### 3.2.3 优先级编码实现

采用移位查找法，从高位（最低优先级）向低位（最高优先级）逐级覆盖：

```verilog
// 优先级编码：找到最低有效位 (req[0] 优先级最高)
// 使用 leading-one-detector 的反向逻辑
// 等价于：从 req[0] 开始，第一个为 1 的位获胜
```

对于 NUM_MASTERS ≤ 32 的情况，使用 generate 循环实现固定优先级逻辑，每位逻辑：

```
gnt_raw[i] = eff_req[i] AND (|eff_req[i-1:0] == 0)
```

这是纯组合逻辑，无反馈环路，时序路径关键看 NUM_MASTERS 的规模。

#### 3.2.4 Flag 生成逻辑

| 标志 | 生成条件 |
|------|----------|
| `granted` | 存在有效请求并获得授权（非停靠状态） |
| `parked` | PARK_MODE = 1 且无有效请求（处于停靠状态） |
| `locked` | 当前处于锁定状态 |

## 4. 配置参数

| 参数 | 取值范围 | 默认值 | 描述 |
|------|----------|--------|------|
| NUM_MASTERS | 2 ~ 32 | 4 | 仲裁器客户端数量 |
| PARK_MODE | 0 / 1 | 1 | 停靠功能使能。1 = 启用，0 = 禁用 |
| PARK_INDEX | 0 ~ NUM_MASTERS-1 | 0 | 停靠客户端索引，无请求时默认授权对象 |
| OUTPUT_MODE | 0 / 1 | 1 | 输出模式。1 = 寄存器输出，0 = 组合输出 |

### 4.1 配置建议

| 应用场景 | 推荐配置 |
|----------|----------|
| 需要最小延迟 | `OUTPUT_MODE = 0`（组合输出） |
| 需要流水线 timing 收敛 | `OUTPUT_MODE = 1`（寄存输出） |
| 不允许无请求时默认授权 | `PARK_MODE = 0` |
| 总线主设备固定优先级仲裁 | `PARK_MODE = 1`，`PARK_INDEX` 设为默认主设备 |
| 需支持独占访问 | 配合 `lock` 信号使用 |

## 5. 接口

### 5.1 信号列表

| 信号名 | 位宽 | I/O | 时钟域 | 描述 |
|--------|------|-----|--------|------|
| clk | 1 | I | clk | 模块工作时钟（上升沿有效） |
| rst_n | 1 | I | — | 异步复位（低电平有效），复位所有寄存器 |
| req | NUM_MASTERS | I | clk | 客户端请求输入，req[i] 对应第 i 个客户端 |
| lock | NUM_MASTERS | I | clk | 锁定控制，lock[i]=1 锁定已授权的客户端 i；不使用该功能时接 `{NUM_MASTERS{1'b0}}` |
| mask | NUM_MASTERS | I | clk | 屏蔽控制，mask[i]=1 屏蔽客户端 i；不使用该功能时接 `{NUM_MASTERS{1'b0}}` |
| gnt | NUM_MASTERS | O | clk | 独热码授权输出，gnt[i]=1 表示客户端 i 获授权（OUTPUT_MODE=1 时寄存器输出） |
| parked | 1 | O | clk | 停靠标志，高表示资源已默认授予 PARK_INDEX（PARK_MODE=0 时恒为 0），输出模式由 OUTPUT_MODE 控制 |
| granted | 1 | O | clk | 授权标志，高表示已将资源授予某个有效请求客户端，输出模式由 OUTPUT_MODE 控制 |
| locked | 1 | O | clk | 锁定标志，高表示仲裁器已被某客户端锁定，输出模式由 OUTPUT_MODE 控制 |

### 5.2 时序约束说明

- 所有输入信号（req、lock、mask）须与 `clk` 同步
- `rst_n` 为异步复位，立即生效，释放需满足 recovery/removal 时序
- `OUTPUT_MODE = 1` 时，gnt、parked、granted、locked 均经一级寄存器输出
- `OUTPUT_MODE = 0` 时，gnt、parked、granted、locked 均为组合输出

## 6. 时序图

### 6.1 基本仲裁时序（OUTPUT_MODE = 1）

```
         ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
clk      │  │  │  │  │  │  │  │  │  │  │  │  │  │  │  │
       ──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──

req[0]    ─────┐           ┌───────────────────────────
               └───────────┘

req[1]         ─────┐     ┌───────────────────────────
                    └─────┘

req[2]    ──────────────────────────────────────────────

gnt[0]           ──────────┐           ┌─────────────────
                            └───────────┘

gnt[1]                     ─────┐           ┌────────────
                                └───────────┘
              ↑          ↑
         req[0]生效    req[1]生效后一个周期
         后一个周期    gnt[1]有效
```

### 6.2 Mask 屏蔽时序

```
clk      ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
       ──┘  └──┘  └──┘  └──┘  └──┘  └──┘

req[0]    ────────────────────────────────────
req[1]    ────────────────────────────────────

mask[0]   ─────────────┐     ┌────────────────
                        └─────┘

gnt[0]    ──────────────┐     ┌───────────────
                         └─────┘
gnt[1]                  ──────┐               ┌──
                               └───────────────┘
```

非锁定状态下，mask[0] 置起后下一周期收回 gnt[0]，重新仲裁后 gnt[1] 获得授权。

### 6.3 Lock 锁定时序

```
clk      ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
       ──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘

req[0]    ─────┐           ┌────────────────────────
               └───────────┘

req[1]    ──────────────────────────────────────────

lock[0]   ─────┐                             ┌─────
               └─────────────────────────────┘

gnt[0]    ─────┐     ┌───────────────────────┐
               └─────┘                       └────
                        （req[1] 被忽略）
locked    ──────────────┐                 ┌────────
                        └─────────────────┘
```

lock[0] 置起后 gnt[0] 持续有效，req[1] 被忽略；lock[0] 释放后下一周期恢复仲裁。

### 6.4 Park 停靠时序

```
clk      ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐  ┌──┐
       ──┘  └──┘  └──┘  └──┘  └──┘  └──┘  └──┘

req[0]    ─────────────────┐     ┌────────────────
                           └─────┘

req[1]    ──────────────────────────────────────────

gnt[0]    ────┐     ┌─────┐     ┌────────────────
              └─────┘     └─────┘
              ↑                 ↑
           park 到          req[0]
           PARK_INDEX=0     仲裁生效

parked    ──────┐           ┌──────────────────────
                └───────────┘
```

无请求时 park 到 PARK_INDEX=0，gnt[0] 有效且 parked 置高；有请求到来后正常仲裁。

### 7.4 时序说明

| 配置 | 时钟约束 | 最大逻辑级数 | 关键路径长度 | Slack | 时序收敛 |
|------|---------|:---:|:---:|:---:|:---:|
| A (N=4, 寄存输出) | 0.7ns | 5 | 0.15ns | +0.43ns | ✅ |
| B (N=32, 寄存输出) | 0.7ns | 7 | 0.18ns | +0.39ns | ✅ |
| C (N=8, 组合输出) | 0.7ns | 5 | 0.16ns | +0.41ns | ✅ |

- **OUTPUT_MODE = 1（寄存输出）**：gnt 经一级寄存器输出，Tco 小，关键路径在寄存器 D 端 setup。逻辑级数随 NUM_MASTERS 增大从 5（N=4）增至 7（N=32）
