## 1. 功能及应用场景

CBB_ARB_2T（Two-Tier Arbiter with Dynamic/Fair-Among-Equal Scheme）是一款参数化同步仲裁器 IP，采用**两层仲裁架构**：

- **第一层**：基于可编程优先级向量进行裁决，每个客户端独立配置优先级，数值越小优先级越高
- **第二层**：在优先级相同的客户端间以**动态公平轮询（Fair-Among-Equals）**机制分配授权，避免饥饿

核心特征：
- 支持 2~32 个客户端并发请求仲裁
- 可编程优先级位宽（1~5 bit），灵活划分优先级等级
- 支持请求屏蔽（Mask）、授权锁定（Lock）、空闲驻留（Park）三种高级控制模式
- 输出支持寄存器化（Registered）与组合逻辑直通（Unregistered）两种模式

**典型应用场景：** 总线仲裁、网络数据调度、SoC 共享资源管理、DMA 控制器等。

### 2.1 两层仲裁 — DS.CBB_ARB_2T.FUNC.001

仲裁器采用两层仲裁架构：

- **第一级（固定优先级）**：每个客户端通过 `prior` 总线独立配置 `P_WIDTH` 位外部优先级，数值越小优先级越高。采用线性遍历贪心查找，从通道 0 到 NUM_MASTERS-1 扫描，选出外部优先级最高的通道集合。优先级由外部配置，不随仲裁轮转自动变化。

- **第二级（轮询 RR）**：仅当多个有效通道拥有相同的第一级优先级时生效。内部维护一个全局轮询指针 `rr_ptr`（位宽 `RR_PTR_WIDTH`），指向本轮搜索起点。在同一优先级组内，从 `rr_ptr` 位置开始循环搜索，选中第一个匹配的有效通道。指针更新规则：当前获胜者持续请求时 `rr_ptr` 保持不变（不强制剥夺）；获胜者撤销请求后 `rr_ptr` 进位至 `(winner + 1) % NUM_MASTERS`。

- **两级关系**：一级优先级不同时高优先直接胜出，第二级不参与；一级优先级相同时由二级 RR 指针裁决。

### 2.2 请求屏蔽 — DS.CBB_ARB_2T.FUNC.002

通过 `mask` 输入端口将特定客户端临时排除在仲裁之外。`mask[i]=1` 时第 i 个客户端不参与本轮仲裁。非锁定状态下，屏蔽当前获授权客户端会立即使其授权失效，下一周期重新仲裁；锁定状态下，屏蔽任何客户端均不影响当前授权。

### 2.3 授权锁定 — DS.CBB_ARB_2T.FUNC.003

已获授权的客户端可通过 `lock` 信号独占资源。`lock[i]=1` 时若 client[i] 已获授权，仲裁器锁定授权至该客户端，忽略其他客户端请求直至锁释放。锁定期间 RR 指针暂停更新（冻结），解锁后从冻结位置继续轮询。

### 2.4 空闲驻留 — DS.CBB_ARB_2T.FUNC.004

无请求时可将授权默认驻留到指定客户端（`PARK_INDEX`），省去下一笔请求的仲裁周期。通过 `PARK_MODE` 参数使能，驻留时 `parked` 标志置高，`gnt` 输出指向 `PARK_INDEX` 对应的客户端。

### 2.5 仲裁优先级顺序 — DS.CBB_ARB_2T.FUNC.005

当多个控制条件同时存在时，仲裁器按以下优先级顺序处理：

```
Lock > Mask > 正常仲裁 > Park
```

- **Lock**：若处于锁定状态，直接保持锁定授权，不响应 mask 变化和新的请求
- **Mask**：非锁定状态下，被屏蔽客户端不参与正常仲裁
- **正常仲裁**：无锁定的有效请求按两层仲裁机制裁决
- **Park**：无任何有效请求时，授权驻留至 `PARK_INDEX`

### 2.6 核心配置 — DS.CBB_ARB_2T.CFG.001

通过参数 `NUM_MASTERS`（2~32，默认 4）配置客户端数量；通过参数 `P_WIDTH`（1~5，默认 2）配置每个客户端的优先级位宽，最多划分 2^P_WIDTH 级优先级。

### 2.7 驻留配置 — DS.CBB_ARB_2T.CFG.002

通过参数 `PARK_MODE`（0/1，默认 1）使能驻留功能；通过参数 `PARK_INDEX`（0~NUM_MASTERS-1，默认 0）指定驻留目标客户端。

### 2.8 输出模式 — DS.CBB_ARB_2T.CFG.003

通过参数 `OUTPUT_MODE`（0/1，默认 1）选择输出模式：`1` 为寄存器输出，`gnt` 和状态标志经寄存器打拍，时序路径干净；`0` 为组合逻辑直通，延迟较小但可能引入毛刺。

### 2.9 时钟复位与请求授权接口 — DS.CBB_ARB_2T.INTF.001

| 信号 | 位宽 | I/O | 描述 |
|------|------|-----|------|

| `rst_n` | 1 | I | 异步复位，低有效 |

| `gnt` | NUM_MASTERS | O | 授权输出向量，one-hot 编码 |

### 2.10 控制接口 — DS.CBB_ARB_2T.INTF.002

| 信号 | 位宽 | I/O | 描述 |
|------|------|-----|------|
| `prior` | NUM_MASTERS×P_WIDTH | I | 优先级向量，按 client[NUM_MASTERS-1]...client[0] 顺序拼接 |

| 信号 | 位宽 | I/O | 描述 |

| `granted` | 1 | O | 授权标志，已向活跃请求客户端发出授权时置高 |
| `locked` | 1 | O | 锁定标志，仲裁器被某客户端锁定时置高 |

### 2.12 仲裁延迟 — DS.CBB_ARB_2T.PERF.001

- `OUTPUT_MODE=0`（组合输出）：请求到授权延迟 = 0 个时钟周期（请求当拍经组合逻辑输出授权）
- `OUTPUT_MODE=1`（寄存器输出）：请求到授权延迟 = 1 个时钟周期（请求当拍完成组合仲裁，下一拍寄存器输出授权）

## 3. 方案分析

### 3.1 第一级仲裁 —— 外部配置固定优先级（Fixed Priority）

**数据来源**：每个客户端 i 的优先级 `prio_high_i` 从 `prior` 总线中按 `P_WIDTH` 位切片提取，由顶层外部配置，硬件内部不自动修改该值。数值越小，优先级越高。

**选择算法 —— 线性遍历贪心查找**：

1. 过滤掉 mask 屏蔽的通道，仅保留 `req[i] & ~mask[i]` 为真的有效请求通道
2. 从通道 0 到 NUM_MASTERS-1 固定顺序线性扫描
3. 遍历中持续保存当前最优通道：新通道 `prio_high` **严格小于**当前最优值则替换，大于则跳过
4. 若两个通道 `prio_high` 数值完全相等，第一级无法区分，交给第二级做决胜

**核心特性**：

- **静态**：优先级由外部软件/硬件设定，不随仲裁轮转而自动变化
- **高优抢占**：只要存在更高一级优先级的请求，会直接抢占当前授权
- **缺陷**：同一优先级多通道并发时，单纯一级固定优先级会出现小号通道长期抢占饥饿，依赖第二级解决

---

### 3.2 第二级仲裁 —— 轮询（Round-Robin，仅同一优先级通道生效）

**生效前提**：仅当多个有效通道拥有**完全相同的 prio_high** 时，才启用本层做冲突裁决。一级优先级不同时，第二级不参与比较。

**数据结构**：内部维护一个全局轮询指针 `rr_ptr`，位宽为 `RR_PTR_WIDTH = $clog2(NUM_MASTERS)`，取值范围 0 ~ NUM_MASTERS-1。复位后 `rr_ptr` 初始化为 0。

**选择算法 —— 循环搜索最近者**：

1. 确定最高优先级组：所有有效请求通道中 `prio_high` 最小的值 `best_prio`
2. 以 `rr_ptr` 为搜索起点，按 `rr_ptr → rr_ptr+1 → ... → NUM_MASTERS-1 → 0 → ... → rr_ptr-1` 的循环顺序，找到第一个满足 `prio_high == best_prio` 的有效请求通道
3. 该通道即为本轮授权 winner

**指针更新规则**：

```
若 |effective_req == 0（无任何有效请求）:
    rr_ptr ← (rr_ptr + 1) % NUM_MASTERS   // 空闲自增，指针持续跑
若 req[winner] == 1'b0（获胜者退出请求）:
    rr_ptr ← (winner + 1) % NUM_MASTERS    // 获胜者释放，进位
否则（获胜者仍持续请求）:
    rr_ptr 保持不变                         // 不剥夺，停留
```

Lock 期间指针冻结不更新。复位后 `rr_ptr` 初始化为 0。

**无请求时自增的意义**：空闲期间指针持续循环跑动，避免长时间空闲后指针停在固定位置，使得请求恢复时该位置对应通道获得不公平的优先权。指针始终在动，保证任意时刻请求到来时的搜索起点是公平的。

**轮询推演示例**（NUM_MASTERS=4，client[0]、client[1]、client[2] 均 prio_high 相同）：

```
周期    req[0:2]   rr_ptr   搜索顺序              winner   说明
────    ────────   ──────   ──────────            ──────   ──────
T0      111        0        0→1→2                 0        从 rr_ptr=0 开始，命中 0
T1      111        0        0→1→2                 0        client[0] 持续请求，rr_ptr 不动
T2      111        0        0→1→2                 0        同上
T3      011        0        0→1→2→3→0→1           1        client[0] 撤 → rr_ptr 进位到 1
T4      011        1        1→2→3→0→1             1        client[1] 持续请求，rr_ptr 不动
T5      001        1        1→2→3→0→1→2           2        client[1] 撤 → rr_ptr 进位到 2
T6      001        2        2→3→0→1→2             2        client[2] 持续请求，rr_ptr 不动
T7      000        2        无有效请求              Park    client[2] 撤 → rr_ptr 进位到 3，进入 Park
T8      000        0        无有效请求              Park    |eff_req|=0，rr_ptr 自增 3→0
T9      000        1        无有效请求              Park    rr_ptr 自增 0→1
T10     011        1        1→2→3→0→1             1        请求恢复，从 rr_ptr=1 搜索命中 1
```

**核心特性**：

- **单指针、硬件简单**：仅需一个 `RR_PTR_WIDTH` 位寄存器
- **不强制剥夺**：当前授权者持续请求时不切换，避免无意义的乒乓
- **释放即进位**：授权者主动撤销请求后指针进位，保证长期公平轮转

### 3.3 两级仲裁整体裁决流程

```
输入: req, prior, mask, lock, rr_ptr
输出: gnt

Step 1 — 筛选有效请求:
    effective_req[i] = req[i] & ~mask[i]

Step 2 — 锁定判断（最高优先）:
    若处于锁定状态 → 直接输出 lock_gnt，流程结束，rr_ptr 不更新

Step 3 — Park 判断:
    若 |effective_req == 0:
        Park 模式 → gnt = onehot(PARK_INDEX)，parked = 1
        非 Park  → gnt = 0
        流程结束，rr_ptr ← (rr_ptr + 1) % NUM_MASTERS（空闲自增）

Step 4 — 正常仲裁（两级比较）:
    // 第一级：找出最高外部优先级
    best_prio = 遍历所有 effective_req[i]==1 的通道，取 prio_high 最小值

    // 第二级：在 best_prio 组内 RR 搜索
    从 rr_ptr 开始循环搜索，
    找到第一个 prio_high == best_prio 且 effective_req[i]==1 的通道 → winner

    gnt = onehot(winner)

Step 5 — 指针更新:
    若 req[winner] == 1'b0（获胜者已退出请求）:
        rr_ptr ← (winner + 1) % NUM_MASTERS
    否则:
        rr_ptr 保持不变
```

**两级关系总结**：

```
第一级 prio_high 不同 → 高优先直接胜出，第二级不参与
第一级 prio_high 相同 → 第二级 RR 从 rr_ptr 循环搜索最近者
```

---

### 3.4 关键设计说明

**第一级线性遍历的硬件实现**：Step 4 中"遍历取最小值"在组合逻辑中展开为并行比较树，并非真正的串行扫描。从通道 0 到 NUM_MASTERS-1 的固定遍历顺序仅影响"best_prio 首次出现"时的选择。

**RR 搜索的硬件实现**：循环搜索 `rr_ptr → rr_ptr+1 → ... → 0 → ... → rr_ptr-1` 可通过两级优先编码器实现——先在 `[rr_ptr, NUM_MASTERS-1]` 范围内查找，未命中再在 `[0, rr_ptr-1]` 范围内查找。该逻辑为纯组合电路，单周期完成。

**RR 指针更新时机**：仅正常仲裁产生新授权时更新。Lock 和 Park 期间指针冻结，保证锁定释放或请求恢复后轮询状态延续。

client[0] 和 client[1] 同时请求且优先级相同（均为 1）。T0 时刻 rr_ptr=0，从 0 开始搜索命中 client[0]，T1 时刻 gnt[0] 寄存器输出；T1~T3 期间 client[0] 持续请求，rr_ptr 保持为 0，gnt[0] 持续授权不切换；T3 时刻 client[0] 撤销请求，rr_ptr 进位至 1，从 1 开始搜索命中 client[1]，T4 时刻 gnt[1] 输出；T4~T6 期间 client[1] 持续请求，rr_ptr 保持为 1。当前授权者不强制剥夺，释放后才进位轮转。

```
req[1] _______________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\___________________________
lock[0] ___/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\________

gnt[0] ______________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾

```

T0 时刻 req[0] 有效，T1 时刻 gnt[0] 输出授权，lock[0] 同时拉高进入锁定状态，locked 标志置高；T2~T4 期间 req[1] 拉高但因 Lock 优先级最高被忽略，gnt[0] 持续保持授权；T5 时刻 lock[0] 释放，Lock 解除后正常仲裁，req[1] 获得授权 gnt[1] 输出。

```
         T0      T1      T2      T3      T4
clk    _/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾

req[0:1] ___/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾\___________________

gnt[0] ___________________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾

parked  ____________________________________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
```

T0 时刻 req[0] 和 req[1] 同时拉高，公平轮询后 client[1] 获胜，T1 时刻 gnt[1] 输出；T1 时刻 mask[1] 拉高屏蔽 client[1]，重新仲裁后 client[0] 获胜，T2 时刻 gnt[1] 撤销、gnt[0] 在 T3 时刻输出；T3 时刻 req[0:1] 全部撤销，无有效请求时 parked 拉高，gnt 默认指向 PARK_INDEX；请求到来后退出 Park 状态正常授权；请求撤销后重新进入 Park 状态。
