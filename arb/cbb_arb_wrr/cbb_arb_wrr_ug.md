## 1. 功能及应用场景

CBB_ARB_WRR 是一款基于 **Weighted Round-Robin（加权轮询）优先级策略** 的参数化仲裁器，支持 2~32 个客户端对单一共享资源进行加权公平访问调度。

与传统的 Round-Robin 仲裁器不同，WRR 仲裁器为每个客户端分配独立权重，在一轮完整调度周期内各客户端按其权重比例获得授权次数，实现带宽的精确按比例分配。调度轮询顺序固定（0 → 1 → 2 → … → N-1 循环遍历），保证各客户端在长期内获得与权重匹配的服务机会。

**核心功能：**
- 加权轮询仲裁：基于 WRR 算法，每个端口按 `weight` 输入端口配置的权重获得相应比例的授权次数
- 可编程请求屏蔽：通过 `mask` 输入按位屏蔽指定客户端
- Lock 锁定机制：已授权客户端可通过 `lock` 独占资源，适用于连续传输场景
- Park 停靠机制：无请求时将资源默认授予指定客户端，避免授权悬空并支持快速响应
- 灵活的输出模式：可选寄存器输出以优化时序，或组合逻辑输出以降低延迟

**典型应用场景：**
- SoC 内部多主设备总线仲裁（AHB/AXI 交叉开关），需要 QoS 差异化带宽分配
- 网络交换架构中的加权端口调度
- 多通道 DMA 请求仲裁（不同通道具有不同带宽需求）
- 共享存储器访问控制（高优先级客户端需要更多带宽）

### 2.1 加权轮询（WRR）仲裁 — DS.ARB_WRR.FUNC.001

CBB_ARB_WRR 采用加权轮询（Weighted Round-Robin）策略进行仲裁：

- 每个端口 i 的权重由输入 `weight[(i+1)*WEIGHT_WIDTH-1 : i*WEIGHT_WIDTH]` 指定（取值范围 1~31），代表一轮完整调度内该端口可获得对应权重次数的授权
- 内部为每个端口维护剩余权重计数器 `cnt[i]`（位宽 5bit，复位后初始化为对应权重输入值）
- 调度轮询顺序固定：0 → 1 → 2 → … → N-1 循环遍历
- 仅未被 mask 屏蔽、`req[i] = 1`、`cnt[i] > 0` 的端口具备授权资格
- 获胜端口 `cnt[i]` 减 1；若递减后 `cnt[i]` 仍大于 0，`priority_ptr` 保持为 `i`，否则移到 `(i + 1) % NUM_MASTERS`
- 一轮调度结束时——即所有有请求（经 mask 过滤后）且未锁定的端口中，再无任何端口剩余权重>0——统一重置所有端口 `cnt[i]` 为当前 `weight` 输入端口的对应权重值，`priority_ptr` 归零。不请求或被屏蔽的端口不阻止轮次推进（Work-Conserving）

### 2.2 Lock 锁定机制 — DS.ARB_WRR.FUNC.002

Lock 机制允许已获得授权的客户端独占共享资源，适用于 DMA 传输等需要连续占用资源的场景：

- **进入锁定**：客户端 i 获得授权后，置起 `lock[i] = 1`，仲裁器进入锁定状态
- **锁定行为**：锁定期间当前客户端持续占用资源，其他所有客户端的请求均被屏蔽，加权轮询暂停，剩余权重计数器保持不变
- **退出锁定**：客户端释放 `lock[i] = 0` 后，下一时钟周期仲裁器退出锁定状态，重新进行加权轮询仲裁。轮询指针更新为 `(i + 1) % NUM_MASTERS`
- **状态指示**：锁定状态通过 `locked` 输出标志指示（高电平有效）
- **约束**：仅当前已获授权的客户端可锁定；未授权客户端置起 `lock` 无效

### 2.3 请求屏蔽 — DS.ARB_WRR.FUNC.003

通过 `mask` 输入信号按位屏蔽指定客户端的请求：

- `mask[i] = 1` 时，客户端 i 的请求被屏蔽，不参与本轮仲裁
- `mask` 对 `req` 的屏蔽为纯组合逻辑，同一时钟周期内生效
- 被屏蔽的请求不影响轮询指针的推进
- 被屏蔽端口的剩余权重计数器不参与本轮递减判断
- 当所有未屏蔽客户端均无请求时，`granted` 置低（无 Park 模式下）
- **注意**：Lock 锁定期间，`mask` 信号对已锁定的客户端无效（锁定客户端不受 mask 影响）

### 2.4 Park 停靠机制 — DS.ARB_WRR.FUNC.004

Park 机制在无任何客户端发起请求时，将资源默认授予指定客户端，避免授权信号悬空：

- 当 `PARK_MODE = 1` 且所有 `req[i]` 均为 0（经 mask 过滤后）时，`gnt[PARK_INDEX] = 1`，`granted = 1`，`parked = 1`
- 任意客户端发起有效请求后，退出停靠，进入正常加权轮询仲裁
- `PARK_MODE = 0` 时停靠禁用，无请求时 `gnt` 全 0，`granted = 0`

### 2.5 优先级顺序 — DS.ARB_WRR.FUNC.005

当 Lock、WRR 加权轮询、Park 同时存在时，优先级从高到低为：

**Lock > WRR 加权轮询（mask 过滤） > Park**

- Lock 锁定期间，gnt 固定为锁定客户端，加权轮询和 Park 均被屏蔽，剩余权重计数器保持不变
- 无 Lock 且有请求时，加权轮询生效：mask 对 req 做屏蔽过滤后按固定顺序轮询扫描，找到首个满足 `cnt[i] > 0` 的端口授权
- 无 Lock 且无请求时，Park 生效，gnt 输出 PARK_INDEX 的默认值

### 2.6 权重耗尽自动重置 — DS.ARB_WRR.FUNC.006

每轮调度的结束条件为：**所有有请求（经 mask 过滤后）的端口 `cnt[i]` 均已耗尽**。不请求或被屏蔽的端口不阻止轮次推进（Work-Conserving），触发时自动重置：

- 检测条件：`~|(req_masked & cnt_nz) == 1`，即经 mask 过滤后的请求端口中，无任何端口 cnt > 0
- 重置动作：所有端口 `cnt[i]` 统一恢复为当前 `weight` 输入端口的对应权重值，轮询指针归零
- 重置与授权在同一周期完成：当前周期仍正常完成仲裁和 cnt 递减，下一周期以重置后的 cnt 参与仲裁
- 边界情况：若某活跃端口权重耗尽而其他活跃端口从未请求，本轮即时结束并重置，活跃端口获得新一轮授权，资源不空闲

### 2.7 单周期仲裁 — DS.ARB_WRR.PERF.001

仲裁器在每个时钟周期内完成一次完整的仲裁决策：

- 组合逻辑路径（`OUTPUT_MODE = 0`）：`gnt` 与 `req` 同周期有效，零延迟仲裁
- 寄存器输出路径（`OUTPUT_MODE = 1`）：`gnt` 相对 `req` 延迟一个时钟周期，改善时序收敛

### 2.8 客户端数量可配置 — DS.ARB_WRR.CFG.001

通过参数 `NUM_MASTERS` 配置仲裁客户端数量：

- 取值范围：2 ~ 32
- 默认值：4
- `req`、`mask`、`lock`、`gnt` 信号位宽及权重计数器数量均由此参数决定

### 2.9 输出寄存器模式 — DS.ARB_WRR.CFG.002

通过参数 `OUTPUT_MODE` 控制输出端是否插入寄存器：

- `OUTPUT_MODE = 0`：输出无寄存器，组合逻辑直接输出，延迟最小
- `OUTPUT_MODE = 1`：输出带寄存器，打一拍输出，改善时序收敛

### 2.10 停靠模式使能 — DS.ARB_WRR.CFG.003

通过参数 `PARK_MODE` 控制停靠机制的启用：

- `PARK_MODE = 0`：停靠逻辑禁用，无请求时无授权输出
- `PARK_MODE = 1`：停靠逻辑使能，无请求时将资源授予 `PARK_INDEX` 指定的客户端
- 默认值：1

### 2.11 停靠目标索引 — DS.ARB_WRR.CFG.004

通过参数 `PARK_INDEX` 指定停靠目标客户端编号：

- 取值范围：0 ~ `NUM_MASTERS` - 1
- 默认值：0
- `PARK_MODE = 1` 时生效，指定无请求时 `gnt` 置位的客户端

### 2.12 时钟与复位 — DS.ARB_WRR.INTF.001

- 所有输入信号（`req`、`mask`、`lock`、`weight`）均在 `clk` 上升沿采样
- `rst_n` 为异步复位，低电平有效，复位所有内部状态（包括轮询指针、锁定状态、停靠状态、剩余权重计数器、输出寄存器）
- 复位后，轮询指针归零，锁定状态清除，停靠状态清除，所有 `cnt[i]` 初始化为输入端口 `weight` 对应段的权重值

### 2.13 请求与授权接口 — DS.ARB_WRR.INTF.002

- `req[NUM_MASTERS-1:0]`：客户端请求信号，高电平有效
- `mask[NUM_MASTERS-1:0]`：客户端屏蔽信号，高电平屏蔽
- `lock[NUM_MASTERS-1:0]`：客户端锁定信号，高电平锁定
- `gnt[NUM_MASTERS-1:0]`：独热码（one-hot）授权输出，同一周期至多一位为高
- `granted`：仲裁有效标志，高电平表示当前存在有效授权（含停靠状态下的默认授权）
- `locked`：锁定状态指示，高电平表示当前处于锁定状态
- `parked`：停靠状态指示，高电平表示当前处于停靠状态（无请求，资源停靠于 PARK_INDEX）

### 2.14 权重输入接口 — DS.ARB_WRR.INTF.003

通过 `weight` 输入端口为每个客户端配置独立权重，支持运行时动态调整：

- `weight[NUM_MASTERS*WEIGHT_WIDTH-1:0]`：扁平化权重输入，每 `WEIGHT_WIDTH` bit 对应一路客户端的权重值
- 端口 i 对应权重段：`weight[(i+1)*WEIGHT_WIDTH-1 : i*WEIGHT_WIDTH]`
- 权重取值范围：1 ~ 31（5bit 无符号整数），`WEIGHT_WIDTH = 5`
- 权重值 0 视为非法输入，行为未定义（外部需保证权重 ≥ 1）
- 权重在 `clk` 上升沿采样，权重变更在下一周期生效
- 轮次完成（所有有请求的端口 cnt 耗尽）重置时，使用当前采样到的 `weight` 值重新装载所有 `cnt[i]`
- 不使用时接 `{NUM_MASTERS*WEIGHT_WIDTH{1'b1}}`（全 1），退化为标准 Round-Robin 行为

## 3. 方案分析

### 3.1 核心原理

加权轮询（WRR）仲裁器的核心是在固定轮询顺序的基础上引入**权重计数器机制**，使各端口在一轮完整调度中获得与权重成比例的授权次数。

与标准 Round-Robin 仲裁器（每次授权后优先级轮转一位）不同，WRR 仲裁器在固定轮询顺序（0→1→2→…→N-1 循环）下，通过递减剩余权重计数器控制各端口的授权次数。当某端口计数器耗尽时，轮询扫描自动跳过该端口；当所有端口计数器均耗尽时，统一重置并开启新一轮调度。

### 3.2 关键设计要素

#### 3.2.1 权重输入与剩余权重计数器

- **权重输入 weight**：`weight[NUM_MASTERS*WEIGHT_WIDTH-1:0]`，扁平化输入端口，每 5bit 对应一路客户端权重（1~31），在 clk 上升沿采样，支持运行时动态调整
- **剩余权重计数器 cnt[i]**：5bit 寄存器，记录当前轮内端口 i 剩余的授权次数
  - 复位后：`cnt[i] = weight[(i+1)*WEIGHT_WIDTH-1 : i*WEIGHT_WIDTH]`
  - 授权后：获胜端口 `cnt[i] = cnt[i] - 1`，其余端口 cnt 不变
  - 轮次完成重置：当所有有请求（经 mask 过滤后）的端口 `cnt[i]` 均已耗尽时，下一周期全部恢复为当前 `weight` 输入端口的对应权重值

#### 3.2.2 轮询指针

维护一个内部寄存器 `priority_ptr`，指示当前正在服务的端口位置，也是本轮扫描的起点。规则如下：

- 复位后，`priority_ptr = 0`
- 每次完成有效授权后：
  - 若获胜端口 `cnt[granted_client]` 递减后 **仍大于 0**：`priority_ptr` 保持为 `granted_client`（下一周期继续优先服务该端口）
  - 若获胜端口 `cnt[granted_client]` 递减后 **等于 0**：`priority_ptr` 更新为 `(granted_client + 1) % NUM_MASTERS`（该端口权重耗尽，移到下一端口）
- 无有效请求时，`priority_ptr` 自增，更新为：（priority_ptr+1）% NUM_MASTERS
- 锁定期间，`priority_ptr` 保持不变（仲裁暂停）
- 轮次完成重置时，`priority_ptr` 归零

#### 3.2.3 加权轮询搜索逻辑

给定 `priority_ptr = p`，仲裁搜索顺序为固定轮询：

```
p, p+1, p+2, ..., NUM_MASTERS-1, 0, 1, ..., p-1
```

在每个搜索位置 i，需同时满足以下条件才可授权：
- `mask[i] == 0`（未屏蔽）
- `req[i] == 1`（有请求）
- `cnt[i] > 0`（剩余权重未耗尽）

采用两级优先编码器（PPC）实现：第一级搜索 `[p : NUM_MASTERS-1]` 范围，第二级搜索 `[0 : p-1]` 范围，两级结果按优先级选择。找到获胜端口并递减 `cnt` 后，根据剩余 cnt 是否为零决定 `priority_ptr` 保持或前进（见 §3.2.2）。

#### 3.2.4 轮次完成检测与重置

轮次完成的检测条件为所有有请求（经 mask 过滤后）的端口 cnt 均已耗尽，即"有请求的端口中不存在 cnt > 0 的端口"。组合逻辑公式如下：

```
cnt_nz[i]    = |cnt[i]                      // 端口 i 的计数器是否非零
round_done   = ~|(req_masked & cnt_nz)      // 有请求的端口中无任何 cnt > 0
```

当 `round_done == 1` 时，`cnt_eff`（有效计数值）直接取 `weight` 输入，授权路径看到的是已重装后的 cnt，因此**重置与授权在同一周期完成**，无空周期插入。

不请求或被屏蔽的端口不参与 `round_done` 判断——它们不阻止轮次完成。这保证了仲裁器在部分端口静默时仍然 Work-Conserving：只要有任何活跃端口等待且权重未耗尽，就继续授权；一旦所有活跃端口权重耗尽，立即开始新一轮。

**注意**：全员持续活跃时 `round_done` 与 `all_cnt_zero` 等价，原有带宽比例和时序图完全不变。

#### 3.2.5 Mask 请求屏蔽

屏蔽逻辑通过组合电路实现：

```
req_masked[i] = req[i] & ~mask[i]
```

被屏蔽的客户端等效于未发出请求，不影响轮询指针的推进，其 cnt 不参与递减。

#### 3.2.6 Lock 锁定机制

Lock 机制的核心是**锁定状态机**：

```
State: NORMAL (locked = 0)
  - 正常 WRR 加权轮询仲裁
  - gnt 由加权轮询搜索逻辑决定
  - 当 granted == 1 且 lock[granted_client] == 1 → 进入 LOCKED 状态

State: LOCKED (locked = 1)
  - gnt 固定为当前锁定客户端（独热码保持不变）
  - granted 保持高电平
  - priority_ptr 保持不变
  - cnt 全部保持不变
  - mask 对锁定客户端无效
  - 当 lock[locked_client] == 0 → 下一拍进入 NORMAL 状态，priority_ptr 更新为 (locked_client + 1) % NUM_MASTERS
```

锁定状态机采用两段式 FSM 实现（组合逻辑次态 + 时序逻辑现态）。

#### 3.2.7 Park 停靠机制

Park 逻辑为纯组合电路，在无有效请求时将 `gnt` 固定为 PARK_INDEX 的独热码：

```
no_valid_req = (req_masked == 0);  // 全 0 表示经 mask 过滤后无任何有效请求
if (PARK_MODE == 1 && no_valid_req):
    gnt_raw = onehot(PARK_INDEX)
    granted_raw = 1'b1
    parked = 1'b1
else:
    gnt_raw = wrr_arb_result
    granted_raw = wrr_arb_vld
    parked = 1'b0
```

#### 3.2.8 输出寄存器

当 `OUTPUT_MODE = 1` 时，在 `gnt`、`granted`、`locked`、`parked` 输出路径上各插入一级寄存器（D Flip-Flop），打断组合逻辑长路径，改善时序收敛。代价是输出增加一个时钟周期的延迟。

### 3.3 带宽分配示例

以 N=3，权重 W[0]=3，W[1]=2，W[2]=1 为例：

- 一轮完整调度总授权次数 = 3 + 2 + 1 = 6 次
- 带宽分配比例：端口 0: 50%、端口 1: 33.3%、端口 2: 16.7%
- 授权序列：0, 0, 0, 1, 1, 2，循环往复

**调度过程推演（假设三个端口持续有请求且未被屏蔽）：**

| 周期 | priority_ptr | cnt[0] | cnt[1] | cnt[2] | 获胜 | 说明 |
|------|--------------|--------|--------|--------|------|------|
| 初始 | 0 | 3 | 2 | 1 | - | 复位后初始状态 |
| T0 | 0 | 3→2 | 2 | 1 | 0 | priority_ptr=0，端口0 cnt>0，授权；cnt[0]仍>0，ptr保持0 |
| T1 | 0 | 2→1 | 2 | 1 | 0 | priority_ptr=0，端口0 cnt>0，授权；cnt[0]仍>0，ptr保持0 |
| T2 | 0 | 1→0 | 2 | 1 | 0 | priority_ptr=0，端口0 cnt>0，授权；cnt[0]=0，ptr移到1 |
| T3 | 1 | 0 | 2→1 | 1 | 1 | priority_ptr=1，端口1 cnt>0，授权；cnt[1]仍>0，ptr保持1 |
| T4 | 1 | 0 | 1→0 | 1 | 1 | priority_ptr=1，端口1 cnt>0，授权；cnt[1]=0，ptr移到2 |
| T5 | 2 | 0 | 0 | 1→0 | 2 | priority_ptr=2，端口2 cnt>0，授权；cnt[2]=0，全员耗尽，ptr归零并重置cnt |
| T6 | 0 | 3→2 | 2 | 1 | 0 | 新一轮开始，priority_ptr=0，端口0授权，ptr保持0 |

## 4. 配置参数

| 参数 | 配置范围 | 默认值 | 描述 |
|------|----------|--------|------|
| `NUM_MASTERS` | 2 ~ 32 | 4 | 仲裁客户端数量，决定 `req`、`mask`、`lock`、`gnt`、`weight` 的位宽及计数器数量 |
| `WEIGHT_WIDTH` | 5 | 5 | 权重位宽，决定 `weight` 输入和 `cnt[i]` 的位宽（固定为 5，支持 1~31） |
| `OUTPUT_MODE` | 0, 1 | 1 | 输出寄存器控制：0 = 组合输出，1 = 寄存器输出 |
| `PARK_MODE` | 0, 1 | 1 | 停靠模式使能：0 = 禁用，1 = 使能（无请求时将资源授予 PARK_INDEX） |
| `PARK_INDEX` | 0 ~ NUM_MASTERS-1 | 0 | 停靠目标客户端编号，PARK_MODE = 1 时生效 |

## 5. 接口

| 信号名 | 位宽 | I/O | 时钟域 | 描述 |
|--------|------|-----|--------|------|
| `clk` | 1 | I | `clk` | 全局时钟，所有输入信号在上升沿采样 |
| `rst_n` | 1 | I | - | 异步复位，低电平有效，复位所有内部状态（含 cnt 初始化） |
| `req` | `NUM_MASTERS` | I | `clk` | 客户端请求信号，高电平有效 |
| `mask` | `NUM_MASTERS` | I | `clk` | 客户端屏蔽信号，`mask[i] = 1` 屏蔽客户端 i，不使用时接 `{NUM_MASTERS{1'b0}}`（全 0） |
| `lock` | `NUM_MASTERS` | I | `clk` | 客户端锁定信号，`lock[i] = 1` 锁定客户端 i，不使用时接 `{NUM_MASTERS{1'b0}}`（全 0） |
| `weight` | `NUM_MASTERS*WEIGHT_WIDTH` | I | `clk` | 各客户端权重输入，每 `WEIGHT_WIDTH` bit 对应一路客户端权重（1~31），不使用时接全 1（等价标准 RR） |
| `gnt` | `NUM_MASTERS` | O | `clk` | 独热码授权输出，`OUTPUT_MODE = 1` 时为寄存器输出 |
| `granted` | 1 | O | `clk` | 仲裁有效标志，高电平表示存在有效授权，`OUTPUT_MODE = 1` 时为寄存器输出 |
| `locked` | 1 | O | `clk` | 锁定状态指示，高电平表示当前处于锁定状态，`OUTPUT_MODE = 1` 时为寄存器输出 |
| `parked` | 1 | O | `clk` | 停靠状态指示，高电平表示当前处于停靠状态（无请求，资源停靠于 PARK_INDEX），`OUTPUT_MODE = 1` 时为寄存器输出 |

**注：** `gnt`、`granted`、`locked`、`parked` 当 `OUTPUT_MODE = 1` 时为寄存器输出，当 `OUTPUT_MODE = 0` 时为组合逻辑输出。

## 6. 时序图

> 以下时序均基于 `OUTPUT_MODE = 1`（寄存器输出），`NUM_MASTERS = 3`，`weight` 输入为 W[0]=3, W[1]=2, W[2]=1。

### 6.1 基础加权轮询仲裁

```
         T0    T1    T2    T3    T4    T5    T6    T7    T8
           _     _     _     _     _     _     _     _     _
clk    ___| |___| |___| |___| |___| |___| |___| |___| |___| |__
              _____
rst_n  ______|     |___________________________________________
              111         111         111         111
req[2:0] _____X_111_X______X_111_X______X_111_X______X_111_X____
               111         111         111         111
mask           X_000_X______X_000_X______X_000_X______X_000_X____
lock           X_000_X______X_000_X______X_000_X______X_000_X____
              001   001   001   010   010   100         001
gnt      _____X_001_X_001_X_001_X_010_X_010_X_100_X_____X_001_X_
              (0)   (0)   (0)   (1)   (1)   (2)         (0)
                     _____             _____       _____
granted  __________/     \___________/     \_____/     \_________
```

**时序说明：** 复位后 W[0]=3,W[1]=2,W[2]=1，cnt 初始化为对应权重。T1~T3：priority_ptr 保持为 0，端口 0 连续获得 3 次授权，cnt[0] 从 3 递减到 0；T3 授权后 cnt[0]=0，priority_ptr 移到 1。T4~T5：priority_ptr 保持为 1，端口 1 连续获得 2 次授权；T5 授权后 cnt[1]=0，priority_ptr 移到 2。T6：端口 2 获得 1 次授权后 cnt[2]=0，全员 cnt 耗尽，下一周期重置 cnt 并 priority_ptr 归零，开始新一轮。

### 6.2 含屏蔽的 WRR 仲裁

```
         T0    T1    T2    T3    T4    T5    T6    T7
           _     _     _     _     _     _     _     _
clk    ___| |___| |___| |___| |___| |___| |___| |___| |__
              111         111         111
req[2:0] _____X_111_X______X_111_X______X_111_X_____
                         _______________
mask[0]  _______________/               \_______________
              010   010   100         010
gnt      _____X_010_X_010_X_100_X_____X_010_X_____
              (1)   (1)   (2)         (1)
```

**时序说明：** mask[0] 置起后端口 0 被屏蔽。由于 W[1]=2，端口 1 先连续获得 2 次授权；cnt[1] 耗尽后 priority_ptr 移到 2，端口 2 获得 1 次授权；全员耗尽后重置。被屏蔽端口不参与本轮授权，mask[0] 释放后端口 0 重新参与仲裁。

### 6.3 Lock 锁定

```
         T0    T1    T2    T3    T4    T5    T6
           _     _     _     _     _     _     _
clk    ___| |___| |___| |___| |___| |___| |___| |__
              111         111
req[2:0] _____X_111_X______X_111_X____________________
                              _____________
lock[0]  ____________________/             \___________
              001   001   001   001        010
gnt      _____X_001_X_001_X_001_X_001_X_____X_010_X___
              (0)   (0)   (0)   (0)         (1)
                     _________________
granted  ___________/                 \________________
                              _______
locked   ____________________/       \_________________
```

**时序说明：** lock[0] 置起后 gnt[0] 持续有效，req[2:1] 被忽略，cnt 全部保持不变（不递减）；lock[0] 释放后下一周期退出锁定，priority_ptr 轮转到 1，恢复 WRR 仲裁。

### 6.4 权重耗尽重置

```
         T0    T1    T2    T3    T4    T5    T6    T7    T8
           _     _     _     _     _     _     _     _     _
clk    ___| |___| |___| |___| |___| |___| |___| |___| |___| |__
              W[0]=2, W[1]=1 (简化为2端口，权重和为3)
              11          11          11          11
req[1:0] _____X_11_X_______X_11_X_______X_11_X_______X_11_X_____
              01    01    10    01    01    10
gnt      _____X_01_X_01_X_10_X_01_X_01_X_10_X___
              (0)   (0)   (1)   (0)   (0)   (1)
              T0:cnt0=1  T1:cnt0=0  T2:cnt1=0  T3:cnt0=1
              cnt1=1     ptr移到1   全部=0      cnt1=1
                                    重置cnt     ptr保持0
                                    ptr归零
```

**时序说明：** N=2，W[0]=2, W[1]=1。T0~T1：priority_ptr 保持 0，端口 0 连续 2 次授权，cnt[0] 递减到 0 后 ptr 移到 1。T2：端口 1 授权后 cnt[1]=0，此时所有 cnt 均为 0，组合逻辑检测到全员耗尽；T3 时钟沿：cnt 自动重置为 weight 输入值、ptr 归零，同一周期正常完成仲裁，端口 0 获得新一轮首次授权，无空周期。

### 6.5 Park 停靠（PARK_MODE = 1，PARK_INDEX = 0）

```
         T0    T1    T2    T3    T4    T5
           _     _     _     _     _     _
clk    ___| |___| |___| |___| |___| |___| |__
              111
req[2:0] _____X_111_X_______000__________111___
              001         001         001
gnt      _____X_001_X_______001_X_______001_X___
              (0)    (停靠) (0)
                     _____

```

**时序说明：** 无请求时进入停靠，gnt 停靠于 PARK_INDEX（客户端 0），parked 置起；req[0] 到达后退出停靠，恢复 WRR 仲裁。

### 7.4 时序说明

以下基于各配置最差路径 slack 反推极限频率（TSMC 12nm, ssgnp0p9v125c, 0.9V）：

| 配置 | 最差路径组 | 逻辑级数 | 路径延时 | 约束周期 | Slack | 极限频率 | 瓶颈分析 |
|------|-----------|---------|---------|---------|-------|---------|---------|
| A (N=4, OM=1) | REGIN | 20 | 0.426 ns | 0.700 ns | +0.0007 | **1.43 GHz** | 输入→寄存器，20 级组合逻辑，slack 微弱正值 |
| B (N=32, OM=1) | REGIN | 41 | 0.468 ns | 0.750 ns | +0.0001 | **1.33 GHz** | 32 端口输入扇出导致 41 级逻辑，被迫降频至 0.750ns |
| C (N=8, OM=0) | REGIN/REGOUT | 29/28 | 0.461 ns | 0.700 ns | 0.0000 | **1.43 GHz** | 组合输出模式，REGOUT 28 级直通逻辑成为额外瓶颈 |


- **REGIN 路径**：`req`/`mask`/`lock`/`weight` 输入 → Mask 逻辑 → cnt>0 资格判断 → 优先编码器 → Lock MUX → Park MUX。逻辑级数随 NUM_MASTERS 增长约 `2 × ceil(log2(N))` 级。
- **REGOUT 路径**（仅 OUTPUT_MODE=0）：仲裁结果 → Park MUX → 直通输出端口，无寄存器隔离。级数约 `ceil(log2(N)) + 3` 级。
- **寄存器输出模式（OUTPUT_MODE=1）的优势**：Config A vs C 同为 N=4~8 量级，寄存器输出将 REGOUT 路径缩短为 0 级（仅寄存器 CK→Q 延时 0.046ns），slack 从 0 提升至 0.484ns。
