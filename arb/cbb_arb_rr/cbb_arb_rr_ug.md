## 1. 功能及应用场景

CBB_ARB_RR 是一款基于 **Round-Robin（轮询）优先级策略** 的参数化仲裁器，支持 2~32 个客户端对单一共享资源进行公平访问调度。

当多个客户端同时发出请求时，仲裁器按照客户端编号循环提升优先级，确保每个请求者在长期内获得均等的资源访问机会，避免低编号客户端被持续饿死（starvation）。

**核心功能：**
- 多客户端公平仲裁：基于 Round-Robin 算法，优先级在每次授权后轮转
- 可编程请求屏蔽：通过 `mask` 输入按位屏蔽指定客户端
- Lock 锁定机制：已授权客户端可通过 `lock` 独占资源，适用于连续传输场景
- Park 停靠机制：无请求时将资源默认授予指定客户端，避免授权悬空并支持快速响应
- 灵活的输出模式：可选寄存器输出以优化时序，或组合逻辑输出以降低延迟

**典型应用场景：**
- SoC 内部多主设备总线仲裁（AHB/AXI 交叉开关）
- 网络交换架构中的端口调度
- 多通道 DMA 请求仲裁
- 共享存储器访问控制

### 2.1 Round-Robin 公平仲裁 — DS.ARB_RR.FUNC.001

CBB_ARB_RR 采用 **Token-based Round-Robin** 策略进行公平仲裁：

- 复位后，`token` 指向客户端 0
- 每个仲裁周期，先判断当前 `token` 指向的客户端是否有有效请求（经 `mask` 过滤后）
  - 若有，则授予该客户端，并把 `token` 推进到 `(该客户端 + 1) % NUM_MASTERS`
  - 若无，则从 `(token + 1) % NUM_MASTERS` 开始循环向上扫描，授予第一个存在请求的客户端，并把 `token` 推进到该客户端的下一位
- 当所有客户端均无有效请求时，`token` 自增模 `NUM_MASTERS` 滚动，避免指针长期锁死
- 公平性本质：无论本次授权落在哪个客户端，下一周期都从它的下一位开始扫描——持续请求的客户端不会因为"上一拍赢了"而继续独占授权，多个客户端同时请求时授权严格按端口顺序轮转，彻底消除端口饥饿

### 2.2 Lock 锁定机制 — DS.ARB_RR.FUNC.002

Lock 机制允许已获得授权的客户端独占共享资源，适用于 DMA 传输等需要连续占用资源的场景：

- **进入锁定**：客户端 i 获得授权后，置起 `lock[i] = 1`，仲裁器进入锁定状态
- **锁定行为**：锁定期间当前客户端持续占用资源，其他所有客户端的请求均被屏蔽，优先级仲裁暂停
- **退出锁定**：客户端释放 `lock[i] = 0` 后，下一时钟周期仲裁器退出锁定状态，重新进行正常优先级仲裁
- **状态指示**：锁定状态通过 `locked` 输出标志指示（高电平有效）
- **约束**：仅当前已获授权的客户端可锁定；未授权客户端置起 `lock` 无效

### 2.3 请求屏蔽 — DS.ARB_RR.FUNC.003

通过 `mask` 输入信号按位屏蔽指定客户端的请求：

- `mask[i] = 1` 时，客户端 i 的请求被屏蔽，不参与本轮仲裁
- `mask` 对 `req` 的屏蔽为纯组合逻辑，同一时钟周期内生效
- 被屏蔽的请求不影响 token 的推进
- 当所有未屏蔽客户端均无请求时，`granted` 置低
- **注意**：Lock 锁定期间，`mask` 信号对已锁定的客户端无效（锁定客户端不受 mask 影响）

### 2.4 Park 停靠机制 — DS.ARB_RR.FUNC.004

Park 机制在无任何客户端发起请求时，将资源默认授予指定客户端，避免授权信号悬空：

- 当 `PARK_MODE = 1` 且所有 `req[i]` 均为 0（经 mask 过滤后）时，`gnt[PARK_INDEX] = 1`，`granted = 1`，`parked = 1`
- 任意客户端发起有效请求后，退出停靠，进入正常仲裁
- `PARK_MODE = 0` 时停靠禁用，无请求时 `gnt` 全 0，`granted = 0`

### 2.5 优先级顺序 — DS.ARB_RR.FUNC.005

当 Lock、Park、正常轮询同时存在时，优先级从高到低为：

**Lock > 正常轮询（mask 过滤） > Park**

- Lock 锁定期间，gnt 固定为锁定客户端，正常轮询和 Park 均被屏蔽
- 无 Lock 且有请求时，正常轮询生效，mask 对 req 做屏蔽过滤后按 Round-Robin 仲裁
- 无 Lock 且无请求时，Park 生效，gnt 输出 PARK_INDEX 的默认值

### 2.6 单周期仲裁 — DS.ARB_RR.PERF.001

仲裁器在每个时钟周期内完成一次完整的仲裁决策：

- 组合逻辑路径（`OUTPUT_MODE = 0`）：`gnt` 与 `req` 同周期有效，零延迟仲裁
- 寄存器输出路径（`OUTPUT_MODE = 1`）：`gnt` 相对 `req` 延迟一个时钟周期，改善时序收敛

### 2.7 客户端数量可配置 — DS.ARB_RR.CFG.001

通过参数 `NUM_MASTERS` 配置仲裁客户端数量：

- 取值范围：2 ~ 32
- 默认值：4
- `req`、`mask`、`lock`、`gnt` 信号位宽均由此参数决定

### 2.8 输出寄存器模式 — DS.ARB_RR.CFG.002

通过参数 `OUTPUT_MODE` 控制输出端是否插入寄存器：

- `OUTPUT_MODE = 0`：输出无寄存器，组合逻辑直接输出，延迟最小
- `OUTPUT_MODE = 1`：输出带寄存器，打一拍输出，改善时序收敛

### 2.9 停靠模式使能 — DS.ARB_RR.CFG.003

通过参数 `PARK_MODE` 控制停靠机制的启用：

- `PARK_MODE = 0`：停靠逻辑禁用，无请求时无授权输出
- `PARK_MODE = 1`：停靠逻辑使能，无请求时将资源授予 `PARK_INDEX` 指定的客户端
- 默认值：1

### 2.10 停靠目标索引 — DS.ARB_RR.CFG.004

通过参数 `PARK_INDEX` 指定停靠目标客户端编号：

- 取值范围：0 ~ `NUM_MASTERS` - 1
- 默认值：0
- `PARK_MODE = 1` 时生效，指定无请求时 `gnt` 置位的客户端

### 2.11 时钟与复位 — DS.ARB_RR.INTF.001

- 所有输入信号（`req`、`mask`、`lock`）均在 `clk` 上升沿采样
- `rst_n` 为异步复位，低电平有效，复位所有内部状态（包括优先级指针、锁定状态、停靠状态、输出寄存器）
- 复位后，优先级指针归零，锁定状态清除，停靠状态清除

### 2.12 请求与授权接口 — DS.ARB_RR.INTF.002

- `req[NUM_MASTERS-1:0]`：客户端请求信号，高电平有效
- `mask[NUM_MASTERS-1:0]`：客户端屏蔽信号，高电平屏蔽
- `lock[NUM_MASTERS-1:0]`：客户端锁定信号，高电平锁定
- `gnt[NUM_MASTERS-1:0]`：独热码（one-hot）授权输出，同一周期至多一位为高
- `granted`：仲裁有效标志，高电平表示当前存在有效授权（含停靠状态下的默认授权）
- `locked`：锁定状态指示，高电平表示当前处于锁定状态
- `parked`：停靠状态指示，高电平表示当前处于停靠状态（无请求，资源停靠于 PARK_INDEX）

## 3. 方案分析

### 3.1 核心原理

Round-Robin 仲裁器的核心是一个**优先级循环轮转**机制。与固定优先级仲裁（FP Arbiter）不同，Round-Robin 仲裁器的最高优先级不是固定的，而是在每次完成仲裁后动态轮转到下一个客户端。这保证了所有客户端在长期内获得均等的服务机会。

### 3.2 关键设计要素

#### 3.2.1 Token 指针（Round-Robin Token）

维护一个内部寄存器 `token`，指示当前仲裁周期中具有最高优先级的客户端编号。规则如下：

- 复位后，`token = 0`（客户端 0 具有最高优先级）
- 若当前 `token` 指向的客户端有有效请求，则授予该客户端，`token` 推进到 `(该客户端 + 1) % NUM_MASTERS`——下一周期从它的下一位开始扫描，保证持续请求时授权仍然轮转
- 若当前 `token` 指向的客户端无有效请求，则扫描 `(token + 1) % NUM_MASTERS` 开始的后继客户端，授予第一个存在请求的客户端，`token` 同样推进到该客户端的下一位
- 当所有客户端均无有效请求时，`token` 自增模 `NUM_MASTERS` 滚动，避免指针长期锁死
- 锁定期间，`token` 保持在锁定客户端；锁定释放后，`token` 更新为 `(locked_client + 1) % NUM_MASTERS`，从锁定客户端的下一位重新开始仲裁

#### 3.2.2 Token 扫描逻辑

给定 `token = t`，当前仲裁周期的扫描顺序为：

```
t, t+1, t+2, ..., NUM_MASTERS-1, 0, 1, ..., t-1
```

即在 `req_masked` 向量中，先判断位 t 是否有有效请求；若有则直接授予该客户端。若无，则从位 `t+1` 开始循环向上扫描，找到第一个有效请求并授予。实现上采用向量旋转 + 优先编码：将 `req_masked` 旋转使位 t 对齐到最低位，对旋转后的向量做优先编码，再反向旋转得到原始索引的独热码授权。

#### 3.2.3 Mask请求屏蔽

屏蔽逻辑通过组合电路实现：

```
req_masked[i] = req[i] & ~mask[i]
```

被屏蔽的客户端等效于未发出请求，不影响优先级指针的推进。

#### 3.2.4 Lock 锁定机制

Lock 机制的核心是**锁定状态机**：

```
State: NORMAL (locked = 0)
  - 正常 Token 扫描仲裁
  - gnt 由 Token 扫描逻辑决定
  - 当 granted == 1 且 lock[granted_client] == 1 → 进入 LOCKED 状态

State: LOCKED (locked = 1)
  - gnt 固定为当前锁定客户端（独热码保持不变）
  - granted 保持高电平
  - token 保持不变
  - mask 对锁定客户端无效
  - 当 lock[locked_client] == 0 → 下一拍进入 NORMAL 状态，token 更新为 (locked_client + 1) % NUM_MASTERS
```

锁定状态机采用两段式 FSM 实现（组合逻辑次态 + 时序逻辑现态）。

#### 3.2.5 Park 停靠机制

Park 逻辑为纯组合电路，在无有效请求时将 `gnt` 固定为 PARK_INDEX 的独热码：

```
if (PARK_MODE == 1 && all_req_masked == 0):
    gnt_raw = onehot(PARK_INDEX)
    granted_raw = 1'b1
    parked = 1'b1
else:
    gnt_raw = normal_arb_result
    granted_raw = normal_arb_vld
    parked = 1'b0
```

#### 3.2.6 输出寄存器

当 `OUTPUT_MODE = 1` 时，在 `gnt`、`granted`、`locked` 输出路径上各插入一级寄存器（D Flip-Flop），打断组合逻辑长路径，改善时序收敛。代价是输出增加一个时钟周期的延迟。

## 4. 配置参数

| 参数 | 配置范围 | 默认值 | 描述 |
|------|----------|--------|------|
| `NUM_MASTERS` | 2 ~ 32 | 4 | 仲裁客户端数量，决定 `req`、`mask`、`lock`、`gnt` 的位宽 |
| `OUTPUT_MODE` | 0, 1 | 1 | 输出寄存器控制：0 = 组合输出，1 = 寄存器输出 |
| `PARK_MODE` | 0, 1 | 1 | 停靠模式使能：0 = 禁用，1 = 使能（无请求时将资源授予 PARK_INDEX） |
| `PARK_INDEX` | 0 ~ NUM_MASTERS-1 | 0 | 停靠目标客户端编号，PARK_MODE = 1 时生效 |

## 5. 接口

| 信号名 | 位宽 | I/O | 时钟域 | 描述 |
|--------|------|-----|--------|------|
| `clk` | 1 | I | `clk` | 全局时钟，所有输入信号在上升沿采样 |
| `rst_n` | 1 | I | - | 异步复位，低电平有效，复位所有内部状态 |
| `req` | `NUM_MASTERS` | I | `clk` | 客户端请求信号，高电平有效 |
| `mask` | `NUM_MASTERS` | I | `clk` | 客户端屏蔽信号，`mask[i] = 1` 屏蔽客户端 i ,不使用时接 `{NUM_MASTERS{1'b0}}`（全 0）|
| `lock` | `NUM_MASTERS` | I | `clk` | 客户端锁定信号，`lock[i] = 1` 锁定客户端 i ,不使用时接 `{NUM_MASTERS{1'b0}}`（全 0）|
| `gnt` | `NUM_MASTERS` | O | `clk` | 独热码授权输出，`OUTPUT_MODE = 1` 时为寄存器输出 |
| `granted` | 1 | O | `clk` | 仲裁有效标志，高电平表示存在有效授权，`OUTPUT_MODE = 1` 时为寄存器输出 |
| `locked` | 1 | O | `clk` | 锁定状态指示，高电平表示当前处于锁定状态，`OUTPUT_MODE = 1` 时为寄存器输出 |
| `parked` | 1 | O | `clk` | 停靠状态指示，高电平表示当前处于停靠状态（无请求，资源停靠于 PARK_INDEX），`OUTPUT_MODE = 1` 时为寄存器输出 |

**注：** `gnt`、`granted`、`locked`、`parked` 当 `OUTPUT_MODE = 1` 时为寄存器输出，当 `OUTPUT_MODE = 0` 时为组合逻辑输出。

### 6.1 基础仲裁（Token 轮转）

```
         T0    T1    T2    T3    T4    T5    T6
          _     _     _     _     _     _     _
clk    __| |___| |___| |___| |___| |___| |___| |__
            _____
rst_n  ____|     |__________________________________
              _______________             _____
req[0]  _____/               \___________/     \_______
                  _______________             _____
req[1]  _________/               \___________/     \___
          _____________________________________
req[3:2]______________________________________
          _____________________________________
lock    _______________________________________
             0001  0001  0010  0010  0001  0001
gnt     _____X_____X_____X_____X_____X_____X_____X_____
             (0)   (0)   (1)   (1)   (0)   (0)
                    _____       _____       _____
granted ___________/     \_____/     \_____/     \_________
```

**时序说明：** 复位后 token 指向客户端 0；T1~T2 期间仅客户端 0 请求，无论 token 指向何处都由它获授权，token 推进后被无请求的端口"绕过"又回到 0，因此 gnt[0] 保持有效；T3 客户端 1 请求时 token 恰在 1，gnt[1] 立即有效；T5 客户端 1 释放后扫描回客户端 0，gnt[0] 再次有效。若此时客户端 0 与客户端 1 同时持续请求，授权将按 0→1→0→1 严格交替。

```
          _     _     _     _     _     _     _
```

**时序说明：** lock[0] 置起后 gnt[0] 持续有效，req[3:1] 被忽略；lock[0] 释放后下一周期退出锁定，token 更新为 1，授权客户端 1。

```
          _____________________________________
req[3:1]______________________________________
             0001        0001        0001        0010
gnt     _____X_0001_X_____X_0001_X_____X_0001_X_____X_0010_X__
             (0)         (0)         (0)         (1)
                    _____
granted ___________/     \_____________________________
                    _______________                     __
parked  ___________/               \___________________
```

**时序说明：** 无请求时进入停靠，gnt 停靠于 PARK_INDEX（客户端 0），parked 置起；req[0] 到达后退出停靠，恢复正常仲裁。

### 7.4 时序说明

**综合约束：** 时钟周期 0.7ns（CLK0_PERIOD=1.0ns × CLK_PERIOD_SCALE_RATIO=0.7），输入延迟 0.14ns（20%），输出延迟 0.07ns（10%），时钟不确定度 0.1ns。TSMC 12nm SS 0.9V 125°C。

**各配置极限频率分析：**

极限频率由关键路径 slack 反推：Fmax = 1 / (Tclk - slack)。

| 配置 | 约束周期 | 关键路径 slack | 极限周期 | 极限频率 | 瓶颈 |
|------|:---:|:---:|:---:|:---:|------|
| A（NUM_MASTERS=4, 寄存器输出） | 0.7ns | 0.1879ns | 0.5121ns | **1953 MHz** | reg-to-reg 内部逻辑 |
| B（NUM_MASTERS=32, 寄存器输出） | 0.7ns | 0.0000ns | 0.7000ns | **1428.6 MHz** | 32 输入优先编码器 + REGIN 路径 |
| C（NUM_MASTERS=4, 组合输出） | 0.7ns | 0.1750ns | 0.5250ns | **1905 MHz** | 纯组合 FEEDTHROUGH 路径（req→gnt） |

> - 配置 A 的寄存器输出隔离了内部组合路径，外部时序宽松，但内部 reg-to-reg 路径决定了极限频率。
> - 配置 B 的 32 输入优先编码器逻辑深度约为 5 级，slack=0，已达约束极限。
> - 配置 C 的组合输出模式减少了寄存器延迟，比配置 A 更快，但 FEEDTHROUGH 路径的 slack 略低于 reg-to-reg 路径。
> - 组合输出模式下，外部逻辑可用时序预算 = Tclk - 输出延迟 = 0.63ns。寄存器输出模式下，外部逻辑可用时序预算同样为 0.63ns，且消除了内部组合逻辑变化的影响。
