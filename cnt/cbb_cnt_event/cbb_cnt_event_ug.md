## 1. 功能及应用场景

### 1.1 核心功能 — DS.CBB_CNT_EVENT.FUNC.001
面向异步脉冲采集的专用计数器，内置两级/三级同步链、边沿检测与防丢失逻辑。异步外部事件经同步去亚稳态后生成单周期使能脉冲完成计数。支持事件累计、频率统计、间隔测量。解决异步事件采样丢失与 metastable 问题。适用于中断统计、硬件错误计数、PMU 性能监测、外设脉冲采集。

集成：
- 两/三级同步链消除 metastable（CDC 标准做法）
- 上升沿检测生成单周期 `event_pulse`（每检测到 `event_in` 一个上升沿，计数器 +1）
- 事件累计计数器
- 计数回绕（wrap-around at MAX+1 → 0）

> **重要说明**：本模块为**纯边沿检测计数器**，不支持电平模式（无 `DETECT_EDGE` 参数）。`event_in` 持续为高期间不会每拍加 1，仅在上升沿产生 1 拍 `event_pulse` 触发一次 +1。若需电平模式计数，应在调用方用门控使能配合 `cbb_cnt_bin` 实现。

### 1.2 应用场景
| 场景 | 说明 |
|------|------|
| 中断统计 | 累计外部中断脉冲次数 |
| 硬件错误计数 | 统计 ECC/parity 错误脉冲 |
| PMU 性能监测 | 采集性能事件脉冲做频率/间隔统计 |
| 外设脉冲采集 | 采集 GPIO/sensor 异步脉冲 |
| 频率统计 | 固定时间窗内计事件数 → 频率 |
| 间隔测量 | 配合时间戳测事件间隔 |

### 1.3 解决的问题 — DS.CBB_CNT_EVENT.FUNC.002
| 问题 | 解决方案 |
|------|---------|
| 异步事件采样丢失 | 同步链 + 边沿检测，保证每个被采样的上升沿计 1 次 |
| Metastable 亚稳态 | 2 级 DFF 同步链（MTBF ↑ ~1000x）；高 fmax 用 3 级 |
| 事件间隔过短丢失 | 见 §2.5 限制说明 |

## 2. 规格

### 2.1 计数行为 — DS.CBB_CNT_EVENT.FUNC.003
每检测到 `event_in` 一次上升沿（经同步链后），`q` 在第 3 拍（SYNC_STAGES=2）或第 4 拍（SYNC_STAGES=3）+1。

### 2.2 控制优先级 — DS.CBB_CNT_EVENT.FUNC.004
```
rst_n (最高) > event_pulse > hold
```

### 2.3 复位行为 — DS.CBB_CNT_EVENT.FUNC.005
异步低复位。复位后 `q = 0`，同步链 `sync_meta1/meta2[/meta3] = 0`，`sync_q = 0`。

### 2.4 计数回绕 — DS.CBB_CNT_EVENT.FUNC.006
`q` 到达 `CNT_MAX` 后再加 1 自动回绕到 0（无饱和保持）。

### 2.5 事件丢失限制 — DS.CBB_CNT_EVENT.PERF.001
由于同步链 + 边沿检测共需 3 拍（SYNC_STAGES=2）或 4 拍（SYNC_STAGES=3）延迟：
- 若 `event_in` 两个上升沿间隔 < 同步链延迟拍数，第二个事件可能被丢失（被合并为同一次上升沿）
- 推荐事件最小间隔 ≥ 5 个 `clk` 周期以保证不丢事件
- 这是 CDC 同步计数器的固有特性，非 bug

### 2.6 同步链级数选择 — DS.CBB_CNT_EVENT.CFG.001
| SYNC_STAGES | 同步链延迟 | MTBF | 适用场景 |
|-------------|-----------|------|---------|
| 2 (默认) | 3 拍 | ~1000x 提升 | 普通场景（典型 1 GHz 下 MTBF 仍满足） |
| 3 | 4 拍 | ~1000000x 提升 | 超高 fmax 或高可靠性场景 |

## 3. 方案分析

### 3.1 原理
异步事件计数器 = 同步链 + 边沿检测 + 计数寄存器：

```
                ┌─────────────────────────────┐
                │      Synchronizer Chain      │
event_in ──────▶│ sync_meta1 → sync_meta2     │──▶ sync_final
(async)         │            (→ sync_meta3)   │      │
                └─────────────────────────────┘      │
                                                     ▼
                                ┌────────────────────────────┐
                                │   Edge Detect              │
              sync_q ◀──────────│ sync_final & ~sync_q       │──▶ event_pulse
              (delay 1 cycle)   └────────────────────────────┘      │
                                                                    ▼
                            ┌────────────────────────────────────────┐
                            │  Counter Register                       │
                            │  if pulse: q <= q + 1 (wrap at MAX)     │
                            └────────────────────────────────────────┘
                                          │
                                          ▼
                                          q
```

### 3.2 同步链原理（CDC 标准做法）
异步信号直接进 DFF 第一级会引发 metastable，第二级 DFF 给亚稳态足够时间收敛：

```
event_in ─┬──────────────────────────────
          │
          ▼  T_setup/T_hold 可能违反
   ┌──────────┐
   │sync_meta1│ ← 可能进入 metastable
   └────┬─────┘
        │  1 clk 后大概率收敛
        ▼
   ┌──────────┐
   │sync_meta2│ ← 稳定逻辑值
   └──────────┘
```

MTBF 公式：`MTBF = e^(t_r/τ) / (f_clk · f_data · T0)`，每加 1 级 DFF，MTBF 指数级提升。

### 3.3 边沿检测原理
```
sync_final ──┬──────┬──────────
             │      │
             ▼      ▼
        ┌──────┐  ┌──┐
        │sync_q│  │~ │  ← 反相
        └──┬───┘  └┬─┘
           │       │
           └───┬───┘
               ▼
              AND ──▶ event_pulse (1 cycle pulse on rising edge)
```

### 3.4 多种实现方法对比
| 方案 | 延迟 | 抗 metastable | 备注 |
|------|------|--------------|------|
| 1 级同步 | 2 拍 | ❌ 不安全 | 禁止用于 CDC |
| **2 级同步（默认）** | 3 拍 | ✅ MTBF ~1000x | 本模块默认 |
| 3 级同步 | 4 拍 | ✅✅ MTBF ~10⁶x | 高 fmax 场景 |
| 延迟链 + 异或 | 2 拍 | ❌ | 不适用 CDC |

### 3.5 选定方法
参数化 2/3 级同步链 + 边沿检测 + 计数器。每个同步 reg 独立 always 块，避免 reset 与组合逻辑冲突。

### 3.6 详细设计步骤
1. 第一级 DFF `sync_meta1` 异步采样 `event_in`
2. 第二级 DFF `sync_meta2` 接 `sync_meta1`（消除 metastable）
3. 可选第三级 DFF `sync_meta3`（SYNC_STAGES=3 时启用，进一步提 MTBF）
4. `sync_q` 寄存 `sync_final`（前一拍值）
5. `event_pulse = sync_final & ~sync_q`（上升沿单周期脉冲）
6. 计数器 `q_reg`：rst_n > event_pulse 优先级更新，MAX 时回绕到 0

## 5. 接口

| 信号名 | 位宽 | I/O | 时钟域 | 类型 | 默认值/复位值 | 描述 |
|--------|------|-----|--------|------|--------------|------|
| clk      | 1 | I | clk    | - | - | 系统时钟 |
| rst_n    | 1 | I | -      | 异步 | - | 异步复位，低有效 |
| event_in | 1 | I | async  | 异步 | - | 异步事件输入（跨时钟域） |
| q        | WIDTH | O | clk | **寄存输出** | **0** | 计数值输出 |

### 5.1 输出类型说明

- `q` 为寄存输出：每个事件脉冲到达时更新，MAX 时回绕到 0

### 5.2 输出默认值/复位值

| 状态 | q | 原因 |
|------|---|------|
| 复位期间（rst_n=0） | 0 | 异步复位 |
| 复位释放后 | 0 | 从 0 开始计数 |
| 事件到达 | q+1 | 同步链检测到上升沿 |
| 回绕（q=MAX 时事件到达） | 0 | MAX+1 自动回绕 |

### 5.3 接口时序约束 — DS.CBB_CNT_EVENT.INTF.001

本模块为同步时序逻辑 + CDC 异步输入，约束分两类：

| 约束项 | 要求 | 说明 |
|--------|------|------|
| clk 周期 | 由 SDC `create_clock` 约束 | 典型 1 ns（1 GHz）@TSMC 12nm |
| event_in 异步输入 | **无 setup/hold 约束** | 跨时钟域异步信号，需经 2-3 级同步链后才能进入计数器 |
| event_in 同步链 | `set_false_path -from event_in -to sync_meta1` | CDC 路径，工具不做时序收敛，由同步链保证 MTBF |
| Tco | q 寄存输出 clk→Q 延迟 | 典型 0.2 ns |
| rst_n 异步释放 | rst_n 释放需同步化 | 异步复位，同步释放（建议在 CRG 模块完成） |
| 事件最小间隔 | ≥ 同步链延迟拍数 + 1 | 避免 event 丢失（见 §2.5） |

> **同步链要求（重要）**：`event_in` 必须经 2 级（SYNC_STAGES=2）或 3 级（SYNC_STAGES=3）DFF 同步链后，
> 才能进入边沿检测与计数器。第一级 DFF `sync_meta1` 可能进入 metastable，第二级 DFF `sync_meta2`
> 给亚稳态足够收敛时间；超高 fmax 或高可靠性场景必须用 3 级同步链（MTBF ↑ ~10⁶x）。
> 同步链各 DFF 独立 always 块，避免 reset 与组合逻辑冲突。

## 6. 时序图

### 6.1 单事件计数时序（SYNC_STAGES=2）— DS.CBB_CNT_EVENT.PERF.002
```
clk      __|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
event_in _____|‾‾‾‾|____________________   ← 异步上升沿 (cycle N)
sync_m1  ____|‾‾‾‾‾‾‾‾|_________________   ← N+1 拍捕获
sync_m2  _______|‾‾‾‾‾‾‾‾|______________   ← N+2 拍
sync_q   ___________|‾‾‾‾‾‾‾‾|___________   ← N+3 拍
evt_pulse________|‾‾‾|___________________   ← N+2 拍脉冲 (sync_m2↑, sync_q=0)
q        _____________________|‾‾‾‾‾‾‾‾‾   ← N+3 拍 +1
```

**关键时序**：`event_in` 上升沿后第 3 个 `clk` 上升沿 `q` 才 +1（2 级同步 + 1 级边沿检测延迟）。

### 6.2 SYNC_STAGES=3 时序
比 SYNC_STAGES=2 多 1 拍延迟，`q` 在第 4 拍 +1。

### 6.3 连续密集事件（事件丢失）
```
clk      __|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_|‾|_
event_in ___|‾|_|‾|_|‾|_|‾|_|‾|________  ← 每 2 拍一个脉冲
sync_m1  ____|‾|‾|‾|‾|‾|‾|‾|‾|‾|_____   ← 脉冲被合并
sync_m2  _______|‾‾‾‾‾‾‾‾‾‾‾‾‾‾|_____
evt_pulse________|‾|_________________   ← 只检测到 1 次上升沿
q        _____________|‾‾‾‾‾‾‾‾‾‾‾‾     ← 只 +1（丢失 3 个事件）
```

### 6.4 计数回绕时序
```
clk      __|‾|_|‾|_|‾|_|‾|_|‾|_
event_in _____|‾‾|___|‾‾|___|‾‾   ← 3 次事件脉冲（间隔 > 5 拍）
q        ...FE|FF |00 |01 |...     ← MAX(FF) 后回绕到 00，再 +1 到 01
```

### 7.4 时序说明

本模块为**同步时序逻辑 + CDC 异步输入**，时序路径分两类：

- **寄存器输出 Tco**：`q` 为寄存输出，clk→Q 延迟典型 0.2 ns（@TSMC 12nm）
- **同步链延迟（CDC 路径）**：`event_in` 经 SYNC_STAGES 级 DFF 同步后才进入边沿检测，
  - SYNC_STAGES=2：3 拍延迟（2 级同步 + 1 级边沿检测）→ `q` 在第 3 个 clk 上升沿 +1
  - SYNC_STAGES=3：4 拍延迟 → `q` 在第 4 个 clk 上升沿 +1
  - 该延迟是 CDC 同步计数器固有特性，非 bug
- **关键路径**：`sync_final → edge_detect (AND) → q_reg +1 → q`，长度与 WIDTH 弱相关
  （+1 加法器宽度影响），无 RCA 进位链负担，fmax 远高于 cbb_cnt_bin
- **CDC false path**：`event_in → sync_meta1` 需在 SDC 中设 `set_false_path`，工具不做时序收敛，
  由同步链 DFF 的 MTBF 保证可靠性
- **rst_n 异步释放**：异步复位，同步释放需在 CRG 模块完成；同步链各 DFF 独立 always 块，
  避免 reset 与组合逻辑冲突
- **事件最小间隔**：`event_in` 两个上升沿间隔 < 同步链延迟拍数时第二个事件可能丢失，
  推荐间隔 ≥ 5 个 clk 周期（见 §2.5）

### 7.5 位宽对频率影响
| WIDTH | 1 ns 约束 slack（实测） | 备注 |
|-------|------------------------|------|
| 8  | MET 0.41 ns | 关键路径短（无 RCA 进位链） |
| 16 | MET 0.36 ns | +1 加法器略增延迟 |
| 32 | MET 0.06 ns | +1 加法器进入关键路径 |
| 64 | MET 0.00 ns（临界） | 64-bit +1 加法器占满时序预算 |

> 实测条件：DC W-2024.09-SP3, tcbn12ffcllbwp7d5t16p96cpdssgnp0p9v125c SS 0.9V/125°C, ZeroWireload,
> SS=2/WW=16/IW=16, 1 ns 约束。本模块 fmax 远高于 cbb_cnt_bin（无 RCA 进位链），关键路径仅为
> 同步链 DFF + 边沿检测 AND + +1 加法器。W=8/SS=2 实测：面积 118.24 µm²（含频窗/间隔统计逻辑），
> 动态功耗 140.3 µW vectorless。

## 8. 验证策略

### 8.1 验证思路

采用 **Reference Model + Scoreboard 自检**架构：

- TB 内置参考模型（behavioral 模拟同步链 + 边沿检测 + 计数器，按 SYNC_STAGES 计算期望 `q_ref`）
- 每拍对比 DUT 输出与期望值，mismatch 立即报错并打印上下文 5 拍波形
- 参数化测试框架：单 TB 覆盖 WIDTH∈{8,16,32}、SYNC_STAGES∈{2,3} 配置矩阵

### 8.2 关键测试点

| 测试点 | 描述 |
|--------|------|
| 单拍事件计数 | event_in 单脉冲，验证 q 在第 3/4 拍 +1 |
| 多拍连续事件 | event_in 周期性脉冲，验证连续计数 |
| 同步链延迟验证 | 检查 sync_meta1/meta2[/meta3]/sync_q 逐级延迟正确 |
| 毛刺过滤（密集事件丢失） | event_in 间隔 < 同步链延迟拍数，验证事件合并/丢失行为符合 §2.5 |
| 事件间隔随机 | event_in 间隔随机化（1~20 拍），统计丢失率 vs 间隔分布 |
| 上升沿单周期脉冲 | event_pulse 仅在 sync_final 上升沿当拍拉高 1 拍 |
| 计数回绕 | q 到达 CNT_MAX 后 +1 自动回绕到 0 |
| 复位恢复 | 运行中拉 rst_n，验证 q/同步链/sync_q 异步立即清零 |
| 异步任意时刻事件 | event_in 上升沿对齐 clk 任意相位（含 setup/hold 违反窗口） |
| SYNC_STAGES 切换 | SYNC_STAGES=2/3 配置参数化，验证延迟拍数差异 |
| 位宽遍历 | WIDTH=8/16/32 配置参数化 |

### 8.3 激励策略

- 定向用例：覆盖所有边界组合（事件丢失临界间隔、回绕点）
- 随机用例：1000+ 组随机 event_in 序列，每序列 1000+ 拍
- 自检：TB 内置 Reference Model + Scoreboard 自动对比 `q`
- 覆盖点：
  - 同步链状态翻转（sync_meta1/2[/3] 各级覆盖）
  - event_pulse 触发覆盖
  - 事件毛刺过滤（间隔 < 同步链延迟拍数的事件合并场景覆盖）
  - 回绕边界（q 在 0↔MAX 跳变）
